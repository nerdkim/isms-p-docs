# S2. 사전 셀프 진단 / 결함 리스크 스코어링

> English: [self-check.md](self-check.md)

`system-grounding.md`를 먼저 적용한 뒤 사용합니다.

```
[작업] 신청기관의 현재 운영 상태를 인증기준에 대조하여 결함 리스크를 사전 진단하십시오.

입력:
- 적용 세트: {{별표7 / 별표7의2 / 별표7의3}}
- 운영 상태 설명(설문 응답 또는 정책/증적 요약): {{입력}}
- (선택) 점검 범위 분야: {{예: 2.5, 2.6}}

[절차]
1. extended/manifest.json 에서 적용 세트의 항목 목록을 확정한다(별표7=101, 7의2=62, 7의3=65).
2. extended/index/defect-rulebook.json 의 항목별 결함사례와, 각 항목 .md 의 "주요 확인사항"을 점검 룰로 사용한다.
3. 각 항목을 충족 / 부분충족 / 미충족 / 판단보류 4단계로 분류하고, 판단 근거가 된 결함사례를 인용한다.
4. 빈출 병목영역(2.5 인증 및 권한관리, 2.6 접근통제, 2.7 암호화, 2.9 운영관리)에 가중치를 두어 우선순위를 매긴다.
5. "미충족"과 "판단보류", 중결함 후보는 사람이 결론을 내도록 표시한다(AI는 후보만 제시).

[출력] templates/self-assessment.md 양식으로 작성하여
extended/outputs/checklists/self-assessment-<조직>-<날짜>.md 로 저장한다.
```
