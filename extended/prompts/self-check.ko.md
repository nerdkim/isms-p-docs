# S2. 사전 셀프 진단 / 결함 리스크 스코어링

> English: [self-check.md](self-check.md)

`system-grounding.ko.md`를 먼저 적용한 뒤 사용합니다.

```
[작업] 신청기관의 현재 운영 상태를 인증기준에 대조하여 결함 리스크를 사전 진단하십시오.

입력:
- 적용 세트: {{별표7 / 별표7의2 / 별표7의3}}
- 운영 상태 설명(설문 응답 또는 정책/증적 요약): {{입력}}
- (선택) 점검 범위 분야(분야명으로): {{예: 인증 및 권한관리, 접근통제}}

[절차]
1. extended/manifest.json에서 적용 세트의 항목 목록을 확정합니다(별표7=101, 7의2=62, 7의3=65).
2. extended/index/defect-rulebook.json의 항목별 결함사례와, 각 항목 .md의 "주요 확인사항"을 점검 규칙으로 사용합니다.
참고: defect-rulebook.json과 evidence-dictionary.json은 별표 7(한국어)만 담고 있고, 키는 세트 간에
비교할 수 없는 맨 항목번호입니다. 별표 7의2나 7의3 작업에서는 각 항목 자신의 .md(주요 확인사항 / 증적자료 /
결함사례)에서 규칙을 가져옵니다.
3. 각 항목을 충족 / 부분충족 / 미충족 / 판단보류 4단계로 분류하고, 판단 근거가 된 결함사례를 인용합니다.
4. 빈출 병목 분야(인증 및 권한관리, 접근통제, 암호화 적용, 시스템 및 서비스 운영관리)에 가중치를 두어 우선순위를 매깁니다. 분야는 번호가 아니라 manifest의 `subgroup` 값과 대조해 찾습니다. 별표 7의2와 7의3은 번호를 다시 매기므로 같은 번호가 다른 분야를 가리킵니다(위 네 분야는 별표 7에서만 2.5, 2.6, 2.7, 2.9입니다).
5. "미충족"과 "판단보류", 중결함 후보는 사람이 결론을 내도록 표시합니다(AI는 후보만 제시).

[출력] templates/self-assessment.md 양식으로 작성하여
extended/outputs/checklists/self-assessment-<조직>-<날짜>.md로 저장합니다.
```
