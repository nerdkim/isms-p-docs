## Certification criterion

To prevent leakage of operational data during system testing, procedures for the generation, use, management, disposal, and technical protection of test data shall be established and implemented.

## Key checkpoints

1. Is the use of actual operational data restricted during the development and testing of information systems?
2. When operational data must unavoidably be used in the test environment, are control procedures such as approval by the responsible officer, access and leakage monitoring, and deletion of data after testing established and implemented?

## Detailed explanation

> * This item is a **relaxed certification criterion (Annex 7-3)** under the special case of information security management system certification. The certification criterion / key checkpoints above are the relaxed/adjusted official text, while the detailed explanation / related laws / evidence / nonconformity examples below are the contents of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.8.4 Test Data Security], which is the same control area (under the relaxed criterion, they apply within the scope of the certification criterion / checkpoints above).

The use of actual operational data during the development and testing of information systems shall be restricted.

- To prevent the leakage of personal information and important information during system testing, use test data that is generated arbitrarily or created by processing/transforming operational data
- Establish and implement standards/procedures for the transformation and use of test data

When operational data must unavoidably be used in the test environment, control procedures such as approval by the responsible officer, access and leakage monitoring, and deletion of data after testing shall be established and implemented.

- Establish an approval procedure for the use of operational data : define a reporting and approval system according to data importance, etc.
- Establish and implement a data disposal procedure after the test period expires
- Apply access control measures in the test environment for the use of operational data
- Perform monitoring and periodic review of the replication/use of operational data, etc.

## Related laws

_No individual legal provision directly corresponding to this item is specified._

## Evidence (examples)

- Test data status
- Test data generation rules
- If operational data was used in the test environment, the related approval history

## Nonconformity examples

- A case where specific standards and procedures for generating test data to be used on the development server have not been established
- A case where actual operational data is used as test data without valid grounds or approval by the responsible officer and without processing
- A case where, while using actual operational data for testing purposes with prior approval obtained for unavoidable reasons, the same level of access control as the operational database is not applied to the test database
- A case where, after using actual operational data for testing purposes, the actual operational data is not deleted from the test database even though the test has been completed
