## Certification criterion

The network shall be separated according to business purposes, such as for administrators and users, and access control shall be applied through IP management, terminal authentication, and similar measures.

## Key checkpoints

1. Are all paths through which the organization's network can be accessed identified, and is the internal network controlled so that only authorized users can access it in accordance with the access control policy?

## Detailed explanation

> * This item is a relaxed certification criterion (Annex 7-3) under the special case of information security management system certification. The certification criterion and key checkpoints above are the officially relaxed/adjusted text, while the detailed explanation/related laws/evidence/nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for the same control area, Annex 7 [2.6.1 Network Access] (under the relaxed criteria, they apply within the scope of the certification criterion/checkpoints above).

All paths through which the organization's network can be accessed shall be identified, and network access control management procedures shall be established/implemented so that related risks, such as unauthorized access to the network, can be effectively prevented/responded to.

- When assigning IP addresses to information systems, personal information processing systems, PCs, and the like, control the use of unauthorized IP addresses, for example by assigning them in accordance with an approval procedure
- Control internal network access by unauthorized persons and terminals
- Block unnecessary services and ports installed on network equipment, and similar measures

Network zones shall be physically or logically separated according to services, user groups, the importance of information assets, and legal requirements, and access control shall be applied between each zone.

- Through risk assessment, determine the network separation for core business areas and the level of access control between zones

| Access control zone | Example of access control application |
| --- | --- |
| DMZ | Public servers such as web servers and mail servers for external services are located in the DMZ. Direct connections from the internet to internal systems that do not pass through the DMZ are blocked |
| Server farm | Configured separately from other network zones. Apply an access control policy to allow access only by authorized internal users |
| DB zone | The network zone where databases storing important information such as personal information are located is separated from other network zones |
| Operator environment | The operator network zone that operates servers, security equipment, network equipment, and the like is separated from the general user network zone |
| Development environment | The network used for development work (development servers, test servers, and the like) is separated from the operational network |
| External party zone | Network zones used by external personnel (outsourced services, complaint offices, training rooms, and the like) are separated from the internal business network |
| Other | For business networks, establish and operate criteria for separating network segments according to the characteristics and importance of the work. When using cloud services, establish/implement access control criteria that reflect the characteristics of the cloud environment. However, where it is difficult to distinguish the server farm from the database farm considering the size of the enterprise and similar factors, compensating controls (such as host-based access control) need to be applied based on risk assessment results and the like |

- In accordance with the access control policy, control network zones separated from one another using firewalls, network equipment ACLs, and similar means so that only access to the services necessary for performing work between network zones is allowed

Criteria for assigning IP addresses by network segment shall be established, and where important systems such as database servers do not require external connections, private IP addresses shall be assigned so that direct external access is not possible.

- Keep the IP address assignment status up to date, and manage it securely at a confidential level or higher so that it is not leaked externally
- Use a private IP address scheme for the internal network addressing, and apply the NAT (Network Address Translation) function so that the internal addressing scheme is not exposed externally
- When assigning private IP addresses, use the private IP address ranges according to international standards

* Private IP address ranges
  / A Class : 10.0.0.1 ~ 10.255.255.255
  / B Class : 172.16.0.1 ~ 172.31.255.255
  / C Class : 192.168.0.1 ~ 192.168.255.255

When connecting networks with physically remote locations such as IDCs, branches, agencies, partner companies, and customer centers, a secure connection environment shall be configured using leased lines or VPNs (virtual private networks), and similar means.

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Ensure the Safety of Personal Information Article 6 (Access Control)

## Evidence (examples)

- Network configuration diagram
- IP management ledger
- Information asset inventory
- Firewall rules

## Nonconformity examples

- A case where, upon review through the network configuration diagram and interviews, data is transmitted and received over a general internet line when connecting information systems and personal information processing systems used at external branches with servers located in the IDC, so that communication via a VPN or dedicated network specified in the internal regulations is not being carried out
- A case where the IP addresses of some important servers, such as database servers located on the internal network, are set as public IPs contrary to the internal regulations, and network access blocking is not applied
- A case where a server farm is configured, but due to inadequate network access control settings, access from the internal network to the server farm is excessively allowed
- A case where the network provided to external parties (external developers, visitors, and the like) is not separated from the internal business network without any separate control
- A case where, contrary to the internal regulations, protective measures such as MAC address authentication and installation of mandatory security software are not applied, so that the internal network can be accessed and used merely by connecting a network cable
