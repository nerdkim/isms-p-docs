## Certification criterion

The users allowed to access information systems, the access restriction methods, and the secure access means, among others, must be defined and controlled.

## Key checkpoints

1. Are the users allowed to access the operating system (OS) of each information system, the locations from which access is possible, and the means of access defined and controlled?
2. When no work is processed for a certain period of time after connecting to an information system, is the system connection automatically blocked?
3. Are services unrelated to the purpose of use of the information system removed?
4. Are information systems that provide major services operated on independent servers?

## Detailed explanation

> Note: This item is a relaxed certification criterion (Annex 7-3) under the special case of Information Security Management System certification. The certification criterion and key checkpoints above are the official text as relaxed/adjusted, while the detailed explanation, related laws, evidence, and nonconformity examples below are drawn from the "ISMS-P Certification Criteria Guide" for the same control area in Annex 7, [2.6.2 Information System Access] (under the relaxed criteria, they apply within the scope of the certification criterion and checkpoints above).

For each information system such as servers, network systems, and security systems, the users allowed to access the operating system (OS), the locations from which access is possible, and the means of access, among others, must be defined and controlled.

- Account and privilege request/approval procedures
- Granting individual accounts per user and restricting the use of shared accounts
- Periodic review and up-to-date management of account usage status: whether long-unused accounts or unnecessary accounts exist, etc.
- Access location restrictions: restricting the IP address of the person accessing, etc.
- Consideration of strengthened authentication means for special privileges such as administrators: certificates, OTP, etc.
- Application of secure access means: SSH, SFTP
- Access control measures for connections between servers within the same network area, etc.

When no work is processed for a certain period of time after connecting to an information system, the system connection must be automatically blocked.

- Set the session retention time considering the characteristics of each server, the work environment, the magnitude of risk, legal requirements, etc.

Services or ports that are unrelated to the purpose of use of the information system or that could cause a security incident must be identified and removed or blocked.

- Implement additional security functions for insecure services, protocols, and daemons
- Unless there is an unavoidable reason, restrict the use of insecure services/protocols such as Netbios, File-Sharing, Telnet, and FTP, and use secure technologies such as SSH, SFTP, and IPSec VPN

Servers that provide major services must be operated as independent servers.

- Web servers, database servers, and application programs that directly provide services externally or that store/process sensitive information must not be used as shared equipment; use independent servers instead

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Ensure the Safety of Personal Information Article 6 (Access Control)

## Evidence (examples)

- List of information system operating system accounts
- Server security settings
- Server access control policy (SecureOS management screen, etc.)
- Server and network configuration diagram
- List of information assets

## Nonconformity examples

- When a server administrator in the office accesses a Windows server located in an IDC using the terminal service, but no session timeout is set for the terminal service, so the session is not blocked even when no work is done for a long time
- When connections between servers are not properly restricted, so a specific user, after connecting to a server authorized to them, can pass through that server to also connect to other unauthorized servers
- When access is made using insecure connection protocols (telnet, ftp, etc.) without a valid reason or compensating controls, and unnecessary services and ports are left open
- When the access control policy requires all access to servers to go through the server access control system, but a bypass route exists that allows access to servers without going through the server access control system
