# 2.9.3 Log and Access Record Management  _( Annex 7-3 )_

| Field | Value |

## Certification criterion

Log types (such as user access records, system logs, and privilege grant histories), retention periods, and retention methods for information systems must be defined, and such logs must be securely retained and managed so that they are not forged/altered, stolen, or lost.

## Key checkpoints

1. Has a log management procedure for information systems been established, and are the necessary logs generated and retained accordingly?
2. Are the log records of information systems securely retained so that they are not forged/altered, stolen, or lost, and are access privileges to log records granted on a minimized basis?
3. Are the access records for the personal information processing system securely retained for a certain period, including all necessary items so as to comply with legal requirements?

## Detailed explanation

> * This item is a **relaxed certification criterion (Annex 7-3)** under the special provisions for information security management system certification. The certification criterion/key checkpoints above are the official text as relaxed/adjusted, while the detailed explanation/related laws/evidence/nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.9.4 Log and Access Record Management], which is the same control area (under the relaxed criterion, they apply within the scope of the certification criterion/checkpoints above).

A log management procedure must be established for information systems such as servers, applications, security systems, and network systems, and the necessary logs must be generated and retained accordingly.

- Identify the log types requiring retention and the target systems

  * Major log types (examples)
  - System event logs: logs generated by operating system components (system startup, shutdown, status, error codes, etc.)
  - Network event logs: IP address assignment, traffic logs for major segments
  - Security system logs: administrator access, registration/change/deletion of security policies (rule sets), etc.
  - Security-related audit logs: user access records, authentication success/failure logs, file access, account and privilege registration/change/deletion, etc. (servers, applications, security systems, network systems, databases, etc.)
  - Personal information processing system access records: the accessor's account, access date and time, access location information, information about the data subject processed, the task performed, etc., which make it possible to identify the fact that a personal information handler accessed the personal information processing system
  - Other information-security-related logs

- Define the log format, retention period, log retention (backup) method, etc. for each system and device

- Establish a log management procedure and generate/retain logs accordingly

The log records of information systems must be securely retained so that they are not forged/altered, stolen, or lost, and access privileges to log records must be granted on a minimized basis.

- Log records must be backed up using a separate storage device such as storage, and the granting of access privileges to log records must be minimized so that forgery/alteration and deletion of log records by unauthorized persons do not occur

The access records for the personal information processing system must be recorded electronically, including all necessary items so as to comply with legal requirements, and securely retained for a certain period.

- Items that must be included in personal information processing system access records

  | Item | Description |
  | --- | --- |
  | Identifier | Identification information of the accessor, such as the personal information handler's ID |
  | Access date and time | The time of access or the time the task was performed (year/month/day and hour/minute/second) |
  | Access location information | The accessor's IP address, etc. |
  | Information about the data subject processed | The data subject's ID, customer number, student number, employee number, etc. |
  | Task performed | Inquiry, change, entry, deletion, output, download, etc. of personal information |

- Retention period of personal information processing system access records

  | Field | Retention period |
  | --- | --- |
  | Personal information handler's access records - where the personal information processing system processes the personal information of 50,000 or more data subjects | At least 2 years |
  | Personal information handler's access records - where the personal information processing system processes unique identification information or sensitive information | At least 2 years |
  | Personal information handler's access records - where, as a personal information controller, the entity is a common telecommunications business operator that has registered under Article 6(1) of the Telecommunications Business Act or filed a report under the proviso of the same paragraph | At least 2 years |
  | Where none of the three conditions above apply | At least 1 year |

- Personal information access records must be securely retained so that they are not forged/altered, stolen, or lost

  * Methods for securely retaining access records (examples)
  - Continuously back up access records and store them on a separate auxiliary storage medium, a separate storage device, object storage, etc. other than the personal information processing system
  - To prevent forgery/alteration of access records, use overwrite-prevention media such as CD-ROM, DVD-R, and WORM (Write Once Read Many)
  - When backing up access records to modifiable media (hard disks, magnetic tapes, etc.), store/manage information that can verify forgery/alteration (MAC values, digital signature values, etc.) on a separate device to ensure integrity

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Ensure the Safety of Personal Information Article 8 (Retention and Inspection of Access Records)

## Evidence (examples)

- Log management procedure
- Log record details
- Access control records for log storage devices
- Personal information access record details

## Nonconformity examples

- Where detailed standards and procedures for log recording targets, methods, retention periods, review cycles, responsible persons, etc. have not been established
- Where the maximum size of important logs such as security event logs and application and service logs (Windows Server 2008 or higher) is not set sufficiently large, so they are not recorded/retained for the period specified in internal standards
- Where log records for important Linux/UNIX-family servers are not separately backed up or properly protected, so that users' command execution records, access history, etc. can be deleted at will
- Where, upon reviewing the records of access to the personal information processing system, the accessor's account, access date and time, and accessor's IP address information are retained, but information related to the data subject processed and the task performed (inquiry, change, deletion, download, etc.) is not retained
- Where, due to insufficient capacity of the log server, personal information processing system access records remain for only 2 months
- Where a personal information controller retains the personal information handler's access records for a personal information processing system that processes the personal information of 100,000 data subjects for only 1 year
