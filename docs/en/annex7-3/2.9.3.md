# 2.9.3 Log and Access Record Management  _( Annex 7-3 )_

| Field | Value |
|---|---|

## Certification criterion

Log types (such as user access records, system logs, and privilege grant histories), retention periods, and retention methods for information systems must be defined, and such logs must be securely retained and managed so that they are not forged/altered, stolen, or lost.

## Key checkpoints

1. Has a log management procedure for information systems been established, and are the necessary logs generated and retained accordingly?
2. Are the log records of information systems securely retained so that they are not forged/altered, stolen, or lost, and are access privileges to log records granted on a minimized basis?
3. Are the access records for the personal information processing system securely retained for a certain period, including all necessary items so as to comply with legal requirements?

## Detailed explanation

> ※ This item is a **relaxed certification criterion (Annex 7-3)** under the special provisions for information security management system certification. The certification criterion and key checkpoints above are the official relaxed/adjusted text; the detailed explanation, related laws, evidence, and nonconformity examples below are the "ISMS-P Certification Criteria Guide" content for Annex 7 [2.9.4 Log and Access Record Management], which belongs to the same control domain (it applies within the scope of the certification criterion and key checkpoints above).


For information systems such as servers, applications, security systems, and network systems, the organization must establish log management procedures and, in accordance with these procedures, generate and retain the necessary logs.

- Identify the log types requiring retention and the target systems

  ※ Major log types (examples)
  - System event logs : logs generated by operating system components (system start, shutdown, status, error codes, etc.)
  - Network event logs : IP address allocation, traffic logs for major segments
  - Security system logs : administrator access, registration/change/deletion of security policies (rule sets), etc.
  - Security-related audit logs : user access records, authentication success/failure logs, file access, account and privilege registration/change/deletion, etc. (servers, applications, security systems, network systems, databases, etc.)
  - Personal information processing system access records : items that make it possible to identify the fact that a personal information handler accessed the personal information processing system, such as the accessor account, access date and time, access location information, information about the data subjects processed, and the tasks performed
  - Other information protection-related logs

- Define the log format, retention period, and log retention (backup) method for each system and device

- Establish log management procedures and generate/retain logs accordingly

The log records of information systems must be safely retained so that they are not tampered with, altered, stolen, or lost, and access privileges to the log records must be granted on a minimized basis.

- Log records must be backed up using a separate storage device such as storage, and the granting of access privileges to the log records must be minimized so that tampering, alteration, or deletion of log records by unauthorized persons does not occur

Access records for the personal information processing system must be electronically recorded and safely retained for a certain period, including all necessary items so as to comply with legal requirements.

- Items that must be included in the personal information processing system access records

  | Item | Description |
  | --- | --- |
  | Identifier | Identification information of the accessor, such as the personal information handler ID |
  | Access date and time | The time of access or the time the task was performed (year/month/day and hour/minute/second) |
  | Access location information | The accessor's IP address, etc. |
  | Information about the data subject processed | The data subject's ID, customer number, student number, employee number, etc. |
  | Task performed | Personal information inquiry, change, entry, deletion, output, download, etc. |

- Retention periods for personal information processing system access records

  | Field | Retention period |
  | --- | --- |
  | Access records of personal information handlers - where the system is a personal information processing system that processes the personal information of at least 50,000 data subjects | At least 2 years |
  | Access records of personal information handlers - where the system is a personal information processing system that processes unique identifying information or sensitive information | At least 2 years |
  | Access records of personal information handlers - where the personal information controller is a common telecommunications business operator that has registered under Article 6(1) of the Telecommunications Business Act or reported under the proviso to the same paragraph | At least 2 years |
  | Where none of the above three conditions apply | At least 1 year |

- Personal information access records must be safely retained so that they are not tampered with, altered, stolen, or lost

  ※ Safe retention methods for access records (examples)
  - Perform ongoing backups of access records and store them on separate auxiliary storage media, a separate storage device, object storage, etc., other than the personal information processing system
  - To prevent tampering/alteration of access records, use overwrite-prevention media such as CD-ROM, DVD-R, or WORM (Write Once Read Many)
  - When backing up access records to modifiable media (hard disks, magnetic tapes, etc.), store and manage on a separate device information that can verify whether tampering/alteration has occurred (MAC values, digital signature values, etc.) to ensure integrity

## Related laws

- Personal Information Protection Act, Article 29 (Duty of Safety Measures)
- Standards for Measures to Ensure the Safety of Personal Information, Article 8 (Retention and Inspection of Access Records)

## Evidence (examples)

- Log management procedures
- Log record details
- Access control records for the log storage device
- Personal information access record details

## Nonconformity examples

- Where detailed standards and procedures regarding log recording targets, methods, retention periods, review cycles, responsible personnel, etc. have not been established
- Where the maximum size for important logs such as security event logs and application and service logs (Windows Server 2008 and above) has not been set sufficiently, so that they are not recorded/retained for the period defined by internal standards
- Where log records for important Linux/UNIX-series servers are not separately backed up or appropriately protected, so that users' command execution records, access histories, etc. can be arbitrarily deleted
- Where, upon reviewing the records of access to the personal information processing system, the accessor account, access date and time, and accessor IP address information are retained, but information related to the data subject processed and the task performed (inquiry, change, deletion, download, etc.) is not retained
- Where, due to insufficient log server capacity, the personal information processing system access records remain for only 2 months
- Where a personal information controller retains the personal information handler access records of a personal information processing system that processes the personal information of 100,000 data subjects for only 1 year
