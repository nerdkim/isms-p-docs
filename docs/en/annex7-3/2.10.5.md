## Certification criterion

To protect personal information and important information, information systems, business-use devices, and so on from malicious code such as viruses, worms, Trojan horses, and ransomware, protective measures for prevention, detection, and response to malicious code shall be established and implemented.

## Key checkpoints

1. Are protective measures established and implemented to protect information systems, business-use devices, and so on from malicious code such as viruses, worms, Trojan horses, and ransomware?
2. Are the latest malicious code prevention/detection activities continuously performed through security programs such as antivirus software?
3. Are security programs such as antivirus software kept up to date, and are emergency security updates performed when necessary?
4. When a malicious code infection is discovered, are response procedures such as minimizing the spread of malicious code and damage established and implemented?

## Detailed explanation

> Note: This item is a relaxed certification criterion (Annex 7-3) under the special case for information security management system certification. The certification criterion/key checkpoints above are the relaxed/adjusted official original text, while the detailed explanation/related laws/evidence/nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.10.9 Malicious Code Control], which is the same control area (under the relaxed criterion, they apply within the scope of the certification criterion/checkpoints above).

To protect information systems, business-use devices, and so on from malicious code such as viruses, worms, Trojan horses, and ransomware, protective measures shall be established and implemented including the following content.

- User PC usage guidelines (prohibition of opening unclear emails and files, prohibition of downloading and installing unauthorized programs, and so on)
- Malicious code response guidelines for information systems and personal information processing systems
- Scope of antivirus program installation (information assets subject to possible malicious program infection)
- Antivirus program installation procedures
- Latest malicious code prevention and detection activities through antivirus programs and so on
- Policy for periodic monitoring of malicious code infection through antivirus programs and so on
- Setting the automatic update function of security programs such as antivirus software, or an update method of at least once per day
- Prohibition of installing unauthorized programs such as P2P and web hard drives on information systems and business-use computers
- User education and information provision, and so on

The latest malicious code prevention/detection activities shall be continuously performed through security programs such as antivirus software.

- Inspection of attachments in emails and so on for malicious code infection
- Real-time malicious code monitoring and treatment
- Periodic malicious code inspection: setting an automatic virus inspection schedule
- Keeping the antivirus engine at the latest version: periodic updates, and so on

Security programs such as antivirus software shall be kept up to date, and emergency security updates shall be performed when necessary.

- Compliance with the antivirus update cycle: automatic update or update at least once per day
- Performing updates accordingly when a malicious-program-related alert is issued or when there is an emergency update notice
- When managing antivirus programs using an antivirus central management system, preparing protective measures such as access control for the management server and integrity verification for distributed files

When a malicious code infection is discovered, response procedures such as minimizing the spread of malicious code and damage shall be established and implemented.

- Response procedures when a malicious code infection is discovered (e.g., disconnecting the network cable, and so on)
- Emergency contact network (e.g., antivirus vendor contact person, related agency contact information, and so on)
- Response report form (including discovery date/time, response procedures and methods, responder, and prevention measures), and so on

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Ensure the Safety of Personal Information Article 9 (Prevention of Malicious Programs and so on)

## Evidence (examples)

- Malicious program response guidelines/procedures/manuals
- Antivirus program installation status
- Antivirus program configuration screens
- Malicious program response history (response reports and so on)

## Nonconformity examples

- Where antivirus is not installed on some PCs and servers, or the antivirus engine has not been updated to the latest version for a long period
- Where users can arbitrarily change the antivirus program configuration (real-time scanning, scheduled scanning, update settings, and so on) but no additional protective measures have been established accordingly
- Where the antivirus central management system lacks protective measures such as access control, creating the possibility of a security incident occurring through the central management system, or where integrity verification of antivirus patterns is not performed, creating the possibility of malicious code being spread by a malicious user
- Where multiple malicious code infection histories were identified on some internal network PCs and servers, but the infection status, infection path and cause analysis, and the corresponding remediation records could not be confirmed
