## Certification criterion

Taking into account legal requirements, external threat factors, and the like, a password management procedure used by information system users as well as by data subjects (users) such as customers and members must be established and implemented.

## Key checkpoints

1. Are secure user password management procedures and creation rules for information systems being established and implemented?
2. Are password creation rules being established and implemented so that data subjects (users) can use secure passwords?
3. Are the authentication means of personal information handlers or data subjects being securely applied and managed?

## Detailed explanation

> ※ This item is a relaxed certification criterion (Annex 7-3) under the special cases for information security management system certification. The certification criterion and key checkpoints above are the official text as relaxed/adjusted, while the detailed explanation, related laws, evidence, and nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.5.4 Password Management], which belongs to the same control area (under the relaxed criterion, they apply within the scope of the certification criterion/checkpoints above).

Password management procedures and creation rules must be established and implemented so that users and administrators can set and use secure passwords.

- Examples of password creation rules (enforced systematically except where unavoidable)

| Field | Value |
| --- | --- |
| Applying combination rules | Combine two or more of the following types: letters, numbers, and special characters, with a minimum length of 8 characters<br>If composed of characters only, a minimum length of 10 characters (however, a composition of numbers only may be vulnerable) |
| Setting a change cycle | Set a password validity period and change it periodically (however, whether to change periodically and the change cycle are decided independently, taking into account risk assessment results and the like) |
| Restricting easily guessable passwords | Restrict the use of passwords that are easy to guess, such as repeated identical characters, character strings adjacent on the keyboard, serial numbers, consecutive numbers, birthdays, phone numbers, and other easily guessable personal information, as well as passwords similar to the ID |
| Restricting reuse of identical passwords | Restrict reuse of previously used passwords when changing a password |

- Examples of password management procedures
  - Change the initial or temporary password set at system introduction before use
  - Apply masking when handling passwords (entry, change)
  - Restrict recording/storing passwords on paper, files, mobile devices, and the like, and apply protective measures such as encryption when recording/storing is unavoidable
  - Change the password without delay when an intrusion incident occurs or there are suspected signs of password exposure
  - Perform an identity verification procedure when resetting due to a lost password or the like
  - Manage administrator passwords in accordance with their secrecy grade, and so on

Password creation rules must be established and implemented so that data subjects (users) can set and use secure passwords.

- Refer to the password creation rules for users and personal information handlers, but apply password creation rules at an appropriate level taking into account service characteristics, risk level, and the like
- Prepare a secure reissuance procedure through identity verification and the like in case of a lost or stolen password, and so on

The authentication means of personal information handlers or data subjects must be securely applied and managed.

- When passwords are used as the authentication means of personal information handlers or data subjects, establish and apply secure password creation rules
- When authentication means other than passwords (certificates, PINs, biometrics, security tokens, and the like) are used, apply protective measures so that such authentication means are not seized or misappropriated by unauthorized persons

[Reference] Application/management of the authentication means of personal information handlers or data subjects (Article 5 (5) of the Standards for Measures to Secure the Safety of Personal Information)

⑤ A personal information controller must securely apply and manage the authentication means of personal information handlers or data subjects.

## Related laws

- Personal Information Protection Act Article 29 (Duty of safety measures)
- Standards for Measures to Secure the Safety of Personal Information Article 5 (Management of access authorization)

## Evidence (examples)

- Password setting screens of web pages, information systems, and personal information processing systems
- Password management policies and procedures

## Nonconformity examples

- A case where information security and personal information protection policies, guidelines, and the like set the criteria for password creation rules, but some information systems and personal information processing systems use passwords that differ from the internal guidelines
- A case where internal password regulations require that a temporary password be issued upon password reset and be forcibly changed, but in practice the temporary password is used as is
- A case where internal password regulations set and require compliance with a password change cycle for users and personal information handlers, yet the password is used as is without being changed
