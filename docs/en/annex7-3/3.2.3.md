## Certification criterion

When access is required to information stored in the mobile communications terminal device of the data subject (user) or to functions installed on the mobile communications terminal device, this must be clearly notified so that it can be recognized, and the consent of the data subject (user) must be obtained.

## Key checkpoints

1. When permission to access information stored in the mobile communications terminal device of the data subject (user) or functions installed on the mobile communications terminal device is required, is this clearly notified so that it can be recognized, and is the consent of the data subject (user) obtained?
2. Where an access permission within the mobile communications terminal device is not strictly necessary to provide the relevant service, is service provision not refused even if the data subject (user) does not consent?
3. Are methods provided for the data subject (user) to give and withdraw consent to the relevant access permission within the mobile communications terminal device?

## Detailed explanation

> Note: This item is a relaxed certification criterion (Annex 7-3) under the special case of information security management system certification. The certification criterion / key checkpoints above are the relaxed/adjusted official text, and the detailed explanation / related laws / evidence / nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [3.2.3 Protection of User Terminal Access], which is the same control area (under the relaxed criteria, they apply within the scope of the certification criterion / checkpoints above).

When permission to access information stored in the mobile communications terminal device of the data subject (user) or functions installed on the mobile communications terminal device is required, the relevant matters must be clearly notified so that they can be recognized, and the consent of the data subject (user) must be obtained.

Note: Scope of mobile communications terminal devices
- Applies to smartphones and tablet PCs capable of mobile communications
- 2G mobile communications terminal devices are excluded from the scope, since they are in effect not an environment in which apps can operate
- Devices that do not use the mobile communications network and merely perform functions such as Bluetooth, Wi-Fi, or tethering are excluded from the scope of application
- For smartwatches, considering that it is currently difficult to immediately implement notification/consent functions for access permissions due to constraints such as screen size, it is recommended that only essential access permissions be set for now (however, from the time devices with notification/consent functions implemented are manufactured, the same rules apply as for smartphones and tablet PCs)

- The permissions by which an app can access information stored within a smartphone and installed functions must be minimized to the extent necessary for the service
- Before obtaining consent to access permissions, access permissions that are strictly necessary to provide the relevant service (hereinafter "essential access permissions") and access permissions that are not strictly necessary (hereinafter "optional access permissions") must be distinguished, and after clearly notifying the data subject (user) in an easy-to-understand manner of the items requiring access permission and the reasons therefor, consent to the essential/optional access permissions must be obtained separately from the data subject (user)
  - (For essential access permissions) (1) the items of information and functions requiring the access permission, and (2) the reason access to the relevant information and functions is required, must be notified
  - (For optional access permissions) in addition to (1) and (2) above, (3) the fact that the user may decline to consent to granting the access permission must be notified

Where an access permission within the mobile communications terminal device is not strictly necessary to provide the relevant service, service provision must not be refused even if the data subject (user) does not consent.

Methods must be provided for the data subject (user) to give and withdraw consent to the relevant access permission within the mobile communications terminal device.

- (Operating systems that allow individual consent selection, Android 6.0 or higher and iPhone) Even where the data subject (user) has already consented to an access permission, they can reset the access permission for each app by using the per-app/per-access-permission consent withdrawal function provided by the relevant operating system
- (Operating systems that do not allow individual consent selection) Since a per-access-permission denial function is not implemented, and only essential access permissions were set as a matter of principle, if the data subject (user) wishes to withdraw consent to such essential access permissions, they can delete the already installed app. However, if, despite such an operating system, the app itself has implemented a function that sets optional access permissions and allows the user to choose whether to consent to them, the user can reset the access permission by using the consent withdrawal function provided by the relevant app

Note: For details, refer to the "Guide on Personal Information Protection for Smartphone App Access Permissions"

## Nonconformity examples

- A case where a smartphone app excessively sets permissions to access personal information areas within the smartphone, such as the address book, photos, and text messages, even though they are unnecessary for the service
- A case where an information and communications service provider's smartphone app accesses information stored within the smartphone and installed functions without providing notification of, and obtaining consent to, the access permissions
- A case where, in obtaining consent to a smartphone app's access permissions, a permission that is an optional item is notified as an essential permission when obtaining consent
- A case where a smartphone app supporting Android versions below 6.0, in which individual consent to access permissions is not possible, is distributed with optional access permissions also set, so that the optional access permissions cannot be declined
