## Certification criterion

The work procedures and flows across all areas of the management system shall be identified and documented, and these shall be periodically reviewed to keep them up to date.

## Key checkpoints

1. Are the information service statuses across all areas of the management system identified, and are the work procedures and flows understood and documented?
2. Are the work procedures reviewed periodically in response to changes in services, work, and information assets, so that related documents such as flow diagrams are kept up to date?

## Detailed explanation

> ※ This item is a **relaxed certification criterion (Annex 7-3)** under the special provisions for information protection management system certification. The certification criterion / key checkpoints above are the relaxed/adjusted official original text, while the detailed explanation / related laws / evidence / nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [1.2.2 Status and Flow Analysis], which is the same control area (under the relaxed criterion, these apply within the scope of the certification criterion / checkpoints above).

Status and flow analysis is a preliminary stage of risk analysis and serves as basic material for conducting risk analysis from various perspectives. It can also be effectively used by management to understand the information protection status and to make decisions for risk management.

- Status analysis: identify the differences between the certification criteria and the operational status through a GAP analysis table that compares the certification criteria with the operational status
- Flow analysis: divided into information service flow analysis and personal information processing stage-by-stage flow analysis, with the results diagrammed as a flow table or flow diagram

※ An information service flow diagram refers to an access control conceptual diagram that diagrams, on a user basis, the interconnection of the organization's work procedures, information protection requirements, and security controls
※ A personal information flow diagram refers to a conceptual diagram that diagrams the flow by personal information processing stage (collection, retention, use/provision, destruction) so that it can be viewed at a glance

The information service statuses across all areas of the management system shall be identified, and the work procedures and flows shall be understood and documented.

- Identify the status of all information services within the scope of the management system
- Understand the work procedures and flows for each information service
- Document the work procedures and flows: work status table, work flow diagram, etc.
  - Information service flow diagram (system operator example)

The personal information processing status within the scope of the management system shall be identified, and the flow of personal information shall be understood and documented in the form of a personal information flow table, personal information flow diagram, etc. (in the case of ISMS-P certification).

- (Step 1) Identify the unit tasks in which personal information processing takes place
- (Step 2) Prepare a personal information flow table by personal information lifecycle for each unit task
  - ※ Example of preparing a personal information flow table (source: Guide for Conducting Personal Information Impact Assessments)
    - Collection flow table example
    - Retention/use flow table example
    - Destruction flow table example
- (Step 3) Based on the prepared personal information flow tables, prepare an overall personal information flow diagram and personal information flow diagrams by task so that the flow can be grasped at a glance by personal information processing stage (collection, retention, use/provision, destruction)
  - ※ Example of preparing a personal information flow diagram (source: Guide for Conducting Personal Information Impact Assessments)
    - Personal information flow diagram example - overall (integrated) flow diagram
    - Personal information flow diagram by task (detailed) example

Work procedures and personal information flows shall be reviewed periodically (at least once a year), with reference to the following perspectives, in response to changes in services, work, and information assets, and shall be managed so that they remain up to date.

- Whether existing services, work, and personal information flows have changed (new service launch or reorganization, changes to work procedures, changes to personal information processing methods, organizational changes, changes to external linkage and provision flows, etc.)
- Whether the important information and personal information items being processed have changed
- Whether the types, configuration, functions, etc. of information systems and personal information processing systems have changed
- Whether new personal information processing tasks and flows have arisen
- Whether the external environment has changed, such as amendments to laws and the emergence of new vulnerabilities, etc.

## Related laws

_No individual legal provision directly corresponding to this item is specified._

## Evidence (examples)

- Information service status table
- Information service work flow table / work flow diagram
- Personal information processing status table (in the case of ISMS-P certification)
- Personal information flow table / flow diagram (in the case of ISMS-P certification)

## Nonconformity examples

- Where the work procedures/flows and status of major services within the scope of the management system have not been documented
- Where a personal information flow diagram has been prepared, but there are many parts that differ from the actual flow of personal information, or important personal information flows are omitted
- Where the personal information flow diagram has not been kept current after its initial preparation, so that changed personal information flows are not reflected in the diagram
