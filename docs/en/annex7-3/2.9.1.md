# 2.9.1 Change Management  _( Annex 7-3 )_

| Field | Value |

## Certification criterion

Procedures shall be established and implemented so that information system related assets can be managed, and prior to any change the impact on the system's performance and security shall be analyzed.

## Key checkpoints

1. Are procedures for changes to information system related assets (hardware, operating systems, commercial software packages, etc.) established and implemented?
2. Is the impact on performance and security analyzed before carrying out changes to information system related assets?

## Detailed explanation

> ※ This item is a **relaxed certification criterion (Annex 7-3)** under the special provisions for information security management system certification. The certification criterion and key checkpoints above are the relaxed/adjusted official text, while the detailed explanation / related laws / evidence / nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for the same control area, Annex 7 [2.9.1 Change management] (under the relaxed criteria they apply within the scope of the certification criterion and checkpoints above).

Procedures for changes to information system related assets (hardware, operating systems, commercial software packages, etc.) shall be established and implemented.

- When a change to information system related assets is required, such as an operating system upgrade, installation of commercial software, functional improvement of an application program in operation, network configuration change, or expansion of CPU/memory/storage, an official procedure for the change shall be established and implemented.

  ※ Matters to be included in the change procedure (examples)
  - Change request
  - Review and approval by the responsible person
  - Change confirmation and verification
  - Identification and change of related documents (asset inventory, operation manuals, configuration diagrams, etc.)
  - Change history management, etc.

Prior to carrying out a change to information system related assets, the impact on performance and security shall be analyzed.

- When a change to information system related information assets is required, analyze the impact of the change on security, performance, work, etc. (the need to change policies of security systems such as firewalls, problems and impact levels when policies are changed, etc.)
- Implement changes so that the impact of the change is minimized.
- Consider recovery plans for change failures in advance.

## Related laws

_No individual legal provision directly corresponding to this item is specified._

## Evidence (examples)

- Change management procedures
- Records of change management execution (application/approval, change details, etc.)
- Results of impact analysis for changes

## Nonconformity examples

- A change task was recently performed due to redundancy of the DMZ zone, but no evidence of performing/approving an assessment of the security risks and performance that could arise after the change was confirmed.
- A network change task was recently performed, but because related review and notification were not sufficiently carried out, the change was not properly reflected in the network configuration diagram and in the access control lists (ACLs) of some access control systems (intrusion prevention systems, database access control systems, etc.).
- A change management system was built so that, when an information system is received or changed, the impact on performance and security is analyzed/consulted and related history is managed, but system changes are also possible without going through that system, and the related changes are not properly reviewed.
