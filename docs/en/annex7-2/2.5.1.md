# 2.5.1 Network Access  _( Annex 7-2 )_

| Field | Value |
|---|---|
| Domain | 2. Protection Measure Requirements |
| Section | 2.5 Access Control |
| Item | 2.5.1 Network Access |
| Criterion type | Annex 7-2 (special certification, relaxed certification criteria) |
| Counterpart (Annex 7) | [2.6.1 Network Access](../annex7/2.6.1.md) |

## Certification criterion

To control unauthorized access to wired/wireless networks, management procedures such as IP management and terminal authentication shall be established and implemented, and network separation (DMZ, server farm, DB zone, development zone, etc.) and access control shall be applied according to business purpose and criticality.

## Key checkpoints

1. Are all paths that can access the organization's network identified, and is the internal network controlled so that only authorized users can access it in accordance with the access control policy?
2. Are network zones separated physically or logically according to services, user groups, the criticality of information assets, and legal requirements, and is access control applied between each zone?
3. Are criteria established for assigning IP addresses per network band, and are measures such as assigning private IPs applied when external connection is not required, for example for DB servers?
4. Are protection measures for the transmission section established when connecting the network with physically separated IDCs, branch offices, agencies, etc.?
5. When wireless networks are used for business purposes, are protection measures such as authentication and encryption of transmitted/received data established and implemented to secure the wireless AP and the network section?
6. Are application and termination procedures established and implemented so that only authorized employees can use the wireless network?
7. Are protection measures against unauthorized wireless networks, such as detecting/blocking Ad Hoc connections and unauthorized wireless APs within the organization, established and implemented?

## Detailed explanation

> Note: This item is a relaxed certification criterion (Annex 7-2) under the special provisions for Information Security Management System certification. The certification criterion/key checkpoints above are the official original text as relaxed/adjusted, while the detailed explanation/related laws/evidence/nonconformity examples below are drawn from the "ISMS-P Certification Criteria Guide" for the same control area, Annex 7 [2.6.1 Network Access] (under the relaxed criterion, they apply within the scope of the certification criterion/checkpoints above).

All paths that can access the organization's network shall be identified, and network access control management procedures shall be established and implemented to effectively prevent/respond to related risks such as unauthorized network access.

- Control of unauthorized IP use, such as assigning IP addresses to information systems, personal information processing systems, PCs, etc. through an approval procedure
- Control of internal network access by unauthorized persons and terminals
- Blocking of unnecessary services and ports installed on network equipment, etc.

Network zones shall be separated physically or logically according to services, user groups, the criticality of information assets, and legal requirements, and access control shall be applied between each zone.

- Determining, through risk assessment, the level of network separation of core business areas and access control between zones

| Access control zone | Example of access control application |
| --- | --- |
| DMZ | Public servers such as web servers and mail servers for external services are located in the DMZ. Direct connections from the Internet to internal systems that do not pass through the DMZ are blocked |
| Server farm | Configured separately from other network zones. Access control policy applied to allow access only by authorized internal users |
| DB zone | The network zone where databases storing important information such as personal information are located is separated from other network zones |
| Operator environment | The operator network zone that operates servers, security equipment, network equipment, etc. is separated from the general user network zone |
| Development environment | The network used for development work (development servers, test servers, etc.) is separated from the operational network |
| External party zone | The network zone used by external personnel (outsourced services, civil service desks, training rooms, etc.) is separated from the internal business network |
| Others | For the business network, a network band separation standard is established and operated according to the characteristics and criticality of the work. When using a cloud service, access control standards reflecting the characteristics of the cloud environment are established/implemented. However, when it is difficult to separate the server farm and the database farm considering the scale of the enterprise, etc., supplementary measures need to be applied based on risk assessment results, etc. (host-based access control, etc.) |

- Between network zones separated according to the access control policy, controls are applied using intrusion prevention systems, network equipment ACLs, etc. to allow only access to services necessary for performing work between the network zones

Criteria for assigning IP addresses per network band shall be established, and when important systems such as database servers do not require external connection, they shall be assigned private IPs and configured so that direct external access is not possible.

- Keep the IP address assignment status up to date, and manage it securely at a confidential level or above so that it is not leaked externally
- Use a private IP address scheme for the addressing scheme in the internal network, and apply NAT (Network Address Translation) so that the internal addressing scheme is not exposed externally
- When assigning private IP addresses, use private IP address ranges in accordance with international standards

Note: Private IP address ranges
  / A Class : 10.0.0.1 ~ 10.255.255.255
  / B Class : 172.16.0.1 ~ 172.31.255.255
  / C Class : 192.168.0.1 ~ 192.168.255.255

When connecting the network with physically separated IDCs, branch offices, agencies, partner companies, customer centers, etc., a secure connection environment shall be configured using dedicated lines or VPN (Virtual Private Network), etc.

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Ensure the Safety of Personal Information Article 6 (Access Control)

## Evidence (examples)

- Network configuration diagram
- IP management ledger
- Information asset inventory
- Firewall rules

## Nonconformity examples

- Where, as confirmed through the network configuration diagram and interviews, data is transmitted/received over a general Internet line when connecting information systems and personal information processing systems used at external sites with servers located in the IDC, so that communication using a VPN or dedicated network as specified in internal regulations is not carried out
- Where the IP address of some important servers, such as database servers located in the internal network, is set to a public IP contrary to internal regulations, and network access blocking is not applied
- Where a server farm is configured but, due to inadequate network access control settings, access from the internal network to the server farm is excessively allowed
- Where the network provided to external parties (external developers, visitors, etc.) is not separated from the internal business network without separate controls
- Where, contrary to internal regulations, one can access and use the corporate network simply by connecting a network cable without applying protection measures such as MAC address authentication and installation of mandatory security software
