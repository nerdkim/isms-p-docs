# 2.9.1 Security System Operation  _( Annex 7-2 )_

## Certification criterion

For each type of security system, operational procedures such as designating administrators, updating to the latest policies, changing rulesets, and monitoring events must be established/implemented, and the status of policy application for each security system must be managed.

## Key checkpoints

1. Are operational procedures for the security systems operated by the organization established/implemented?
2. Is the number of personnel allowed access, such as security system administrators, minimized, and is access by unauthorized persons strictly controlled?
3. Is a formal procedure for the new registration, change, and deletion of policies established/implemented for each security system?
4. Is the registration of exception policies for security systems managed in accordance with procedures, and are the users of exception policies managed with the minimum necessary privileges?
5. Is the validity of the policies configured on the security systems reviewed periodically?
6. To prevent illegal access to the personal information processing system and the leakage of personal information, is a security system that performs the functions prescribed by the relevant laws installed and operated?

## Detailed explanation

> ※ This item is a **relaxed certification criterion (Annex 7-2)** under the special provisions for information security management system certification. The certification criterion/key checkpoints above are the official original text as relaxed/adjusted, while the detailed explanation/related laws/evidence/nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.10.1 Security System Operation], which is the same control area (under the relaxed criterion, they apply within the scope of the certification criterion/checkpoints above).

For the security systems operated by the organization, operational procedures that include the following must be established/implemented.

- Designation of a person in charge and an administrator for each type of security system
- Procedures for applying (registering, changing, deleting, etc.) security system policies (rulesets, etc.)
- Method for updating to the latest policies: For security systems such as IDS and IPS, continuous updating of the latest patterns (signatures) and engines to detect new attack techniques
- Security system event monitoring procedures (detecting and verifying anomalies that violate policies, etc.)
- Security system access control policies (user authentication, administrator terminal IP or MAC, etc.)
- Periodic inspection of the security system operation status
- Access control measures for the security system itself, etc.

※ Types of security systems (examples)
- Network security systems: intrusion prevention system (firewall), intrusion prevention system (IPS), intrusion detection system (IDS), network access control (NAC), DDoS response system, virtual private network (VPN), etc.
- Server security systems: system access control, secure operating system (SecureOS)
- Database security systems: database access control
- Information leakage prevention systems: Network DLP (Data Loss Prevention), Endpoint DLP, etc.
- Personal information protection systems: personal information detection solution, printout security, personal information access record management solution, etc.
- Encryption solutions: database encryption, DRM, etc.
- Malware response solutions: antivirus, patch management system (PMS), EDR (Endpoint Detection Response), etc.
- Others: APT response solution, SIEM (Security Incident & Event Monitoring), web application firewall, etc.

The number of personnel allowed access, such as security system administrators, must be minimized, and access by unauthorized persons must be strictly controlled.

- Apply protection measures such as strengthened user authentication (OTP, etc.) and administrator terminal IP or MAC access control to strictly control access by unauthorized persons other than personnel allowed access, such as security system administrators
- Check for access attempts by unauthorized persons through periodic analysis of security system access logs

A formal procedure for the new registration, change, and deletion of policies must be established/implemented for each security system.

- Application and approval procedures for the registration, change, and deletion of policies for each security system, such as firewalls and DLP
- Retain records of security system policy applications/approvals/deployments to ensure accountability
- Considerations when applying security system policies (rulesets)
  - Grant only the minimum privileges necessary for work in accordance with the principle of least privilege
  - Base the network access control policy on blocking all traffic by default, adding and managing only the IPs and Ports that must be allowed for work on an individual basis
  - When configuring security policies, apply them with a limited period of use according to their purpose
  - Manage the registration/change of security policies so that they go through a formal procedure, etc.

The registration of exception policies for security systems must be managed in accordance with procedures, and the users of exception policies must be managed with the minimum necessary privileges.

- Review the validity of the reason for application
- Security review: Conduct a security review based on the exception policy and prepare supplementary measures
- Exception policy application/approval: Approval by the person in charge or the responsible person for each security system
- Monitoring of whether exception policies have expired and of the use of exceptions, etc.

The validity of the policies configured on the security systems must be reviewed periodically, taking into account the following.

- Violations of internal security policies/guidelines (excessively permissive rules, etc.)
- Policies registered without going through a formal approval procedure
- Policies unused for a long period
- Duplicate policies or policies whose period of use has expired
- Policies related to retirees and personnel who have changed duties
- Policies related to exceptions, etc.

To prevent illegal access to the personal information processing system and the leakage of personal information, a security system that performs the functions prescribed by law must be installed and operated.

- Mandatory required functions of the access control system required by the personal information protection related laws
  1. Restrict access privileges to the personal information processing system by IP address, etc., to limit unauthorized access
  2. Analyze the IP addresses, etc., that have accessed the personal information processing system to detect and respond to personal information leakage attempts
- When the personal information processing system is configured in a cloud environment, the access control function can be implemented using the security functions or services provided by the cloud service provider

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Secure the Safety of Personal Information Article 6 (Access Control)

## Evidence (examples)

- Security system configuration
- Network configuration
- Security system operational procedures
- Firewall policies
- Firewall policy setup/change request form
- List of security system exception holders
- Management screens for each security system (firewall, IPS, server access control, DLP, DRM, etc.)
- Security system policy review history

## Nonconformity examples

- When a periodic review of the intrusion prevention system (firewall) security policies is not performed, resulting in numerous unnecessary or excessively permissive policies
- When there are no procedures and standards for the application, change, deletion, and periodic review of security system security policies, or when procedures exist but are not followed
- When management supervision of the status of security system administrator designation and privilege granting is not properly carried out
- When internal guidelines stipulate that the information protection officer records/retains the change history of the security system's security policies, but the policy management ledger is not prepared periodically, or the security policies recorded in the policy management ledger differ from the security policies of the systems actually in operation
