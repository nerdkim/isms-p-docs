## Certification criterion

To prevent leakage of operational data during the system testing process, procedures for the generation, use, management, disposal, and technical protection measures of test data must be established and implemented.

## Key checkpoints

1. Is the use of actual operational data restricted during the development and testing process of the information system?
2. When operational data must unavoidably be used in the test environment, are control procedures such as approval by the responsible person, monitoring of access and leakage, and deletion of data after testing established and implemented?

## Detailed explanation

> Note: This item is a **relaxed certification criterion (Annex 7-2)** under the special case of information security management system certification. The certification criterion / key checkpoints above are the officially relaxed/adjusted original text, and the detailed explanation / related laws / evidence / nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.8.4 Test Data Security], which is the same control area (under the relaxed criterion, they apply within the scope of the certification criterion / checkpoints above).

The use of actual operational data must be restricted during the development and testing process of the information system.

- To prevent personal information and important information from being leaked during the system testing process, test data is used by generating arbitrary data or by processing/converting operational data before use
- Establish/implement standards/procedures for the conversion and use of test data

When operational data must unavoidably be used in the test environment, control procedures such as approval by the responsible person, monitoring of access and leakage, and deletion of data after testing must be established and implemented.

- Establish an approval procedure for the use of operational data: define a reporting and approval system according to data importance, etc.
- Establish and implement a data disposal procedure after the expiry of the test period
- Apply access control measures in the test environment for the use of operational data
- Perform monitoring and periodic review of the replication/use of operational data, etc.

## Related laws

_No individual legal provision directly corresponding to this item is specified._

## Evidence (examples)

- Status of test data
- Rules for generating test data
- Where operational data was used in the test environment, the related approval records

## Nonconformity examples

- Where specific standards and procedures for generating test data to be used on the development server have not been established
- Where actual operational data is used as test data without processing, without a valid reason and without approval by the responsible person
- Where actual operational data is used for testing purposes with prior approval for an unavoidable reason, but the same level of access control as the operational database is not applied to the test database
- Where actual operational data used for testing purposes is not deleted from the test database even after the testing has been completed
