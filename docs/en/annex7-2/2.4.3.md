## Certification criterion

Access by users to information systems and to personal information and important information shall apply secure authentication procedures and, where necessary, strengthened authentication methods. In addition, measures to control access by unauthorized persons, such as limiting the number of login attempts and warning of illegal login attempts, shall be established and implemented.

## Key checkpoints

1. Is access to information systems and personal information processing systems controlled by secure user authentication procedures, such as user authentication, limiting the number of login attempts, and warning of illegal login attempts?
2. When attempting to access a personal information processing system from outside via an information and communications network, are secure authentication means or secure access means applied in accordance with legal requirements?

## Detailed explanation

> ※ This item is a **relaxed certification criterion (Annex 7-2)** under the special provision for information security management system certification. The certification criterion / key checkpoints above are the relaxed/adjusted official text, while the detailed explanation / related laws / evidence / nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.5.3 User Authentication], the same control area (under the relaxed criterion, they apply within the scope of the certification criterion / checkpoints above).

Access to information systems and personal information processing systems shall be controlled in accordance with secure user authentication procedures, such as user authentication, limiting the number of login attempts, and warning of illegal login attempts.

- Examples of user authentication means

  | Field | Authentication means | Remarks |
  | --- | --- | --- |
  | Knowledge-based | Password | Apply secure password composition rules and consider a change cycle<br>Response to password theft, brute-force attacks, etc. is required<br>At the time of system installation, the default account and password provided by the product, etc. must be disabled or changed |
  | Possession-based | Certificate (PKI) | Secure storage of the private key is required (storage on a secure security medium is recommended) |
  | Possession-based | OTP (One Time Password) | Various methods exist, such as OTP tokens and mobile OTP |
  | Possession-based | Other | Smart card method<br>Physical security token method, etc. |
  | Biometrics-based | Fingerprint, iris, face, etc. | Secure management of biometric identification information is required<br>※ Reference: FIDO (Fast Identity Online) |
  | Other methods (can be applied as compensating controls for user authentication) | IP address | A method that restricts access with the corresponding ID to specific IP addresses only |
  | Other methods (can be applied as compensating controls for user authentication) | MAC address | A method that, based on the terminal's MAC address, restricts access to registered terminals only |
  | Other methods (can be applied as compensating controls for user authentication) | Device serial number | A method that restricts access to a specific PC or a specific device (smartphone, etc.) only |
  | Other methods (can be applied as compensating controls for user authentication) | Other | A method that restricts access based on location information, etc. |

- Examples of measures to control account theft and illegal authentication attempts

  | Field | Description |
  | --- | --- |
  | Limiting the number of authentication failures | Restrict access when authentication fails more than a certain number of times<br>※ Standard for Measures to Ensure the Safety of Personal Information, Article 5, Paragraph 6 |
  | Limiting the connection maintenance time | Automatically block the connection when no work has been performed for a certain time after connection (Session Timeout or Idle Timeout, etc.)<br>※ Standard for Measures to Ensure the Safety of Personal Information, Article 6, Paragraph 4 |
  | Limiting concurrent connections | Measures to block connections or a notification function, etc., upon concurrent connection with the same account |
  | Warning of illegal login attempts | Blocking and notification upon access from unregistered IP addresses such as overseas IP addresses<br>Text notification upon weekend or nighttime access<br>Notification upon login with special privileges such as an administrator, etc. |

- When using Single Sign-On (SSO) to provide work convenience, there is a possibility of expanded damage in the event of account theft, so prepare additional protective measures based on risk assessment, such as applying strengthened authentication and requiring re-authentication upon access to important systems

When attempting to access a personal information processing system from outside via an information and communications network such as the internet, secure authentication means shall be applied in accordance with legal requirements; however, in the case of a personal information processing system that processes the personal information of data subjects who are not users, secure access means such as a virtual private network or secure authentication means may be applied.

- Applying secure authentication means refers to applying an additional authentication means beyond the procedure of identifying/authenticating whether a person is a legitimate personal information handler by entering a user account and password into the personal information processing system
- Examples of secure authentication means: certificate, security token, one-time password (OTP), etc.
- When a personal information handler accesses a personal information processing system from outside via an information and communications network, compliance with legal requirements regarding the application of authentication means is required

  | Target personal information processing system | Personal information processing system that processes the personal information of data subjects who are not users | Personal information processing system that processes users' personal information |
  | --- | --- | --- |
  | Items requiring application | Apply secure access means or secure authentication means<br>※ Secure access means: virtual private network (VPN), etc. | Apply secure authentication means |

  [Reference] Applying secure authentication means upon external access (Standard for Measures to Ensure the Safety of Personal Information, Article 6, Paragraph 2)

  ② When a personal information handler attempts to access a personal information processing system from outside via an information and communications network, the personal information controller shall apply secure authentication means such as a certificate, security token, or one-time password. However, in the case of a personal information processing system that processes the personal information of data subjects who are not users, secure access means such as a virtual private network or secure authentication means may be applied.

## Related laws

- Personal Information Protection Act, Article 29 (Obligation to Take Safety Measures)
- Standard for Measures to Ensure the Safety of Personal Information, Article 5 (Management of Access Authority), Article 6 (Access Control)

## Evidence (examples)

- Login screens of information systems and personal information processing systems
- Screen for setting the limit on the number of login attempts
- Login failure message screen
- Procedures for external access (external access application form, list of external accessors, etc.)

## Nonconformity examples

- A case where, when a personal information handler accesses a personal information processing system that processes users' personal information via an open external internet network, secure authentication means are not applied and authentication is performed only by the ID/password method
- A case where, upon login failure of an information system or personal information processing system, it displays in detail that the corresponding ID does not exist or that the password is incorrect, and there is no limit on the number of login failures
