# 2.9.7 Malware Control  _( Annex 7-2 )_

## Certification criterion

To protect personal information and important information, information systems, and business-use terminals, etc. from malware such as viruses/worms/Trojan horses/ransomware, protective measures for malware prevention/detection/response, etc. must be established and implemented.

## Key checkpoints

1. Are protective measures established and implemented to protect information systems and business-use terminals, etc. from malware such as viruses, worms, Trojan horses, and ransomware?
2. Are the latest malware prevention/detection activities continuously performed through security programs such as antivirus software?
3. Are security programs such as antivirus software kept up to date and, when necessary, are emergency security updates performed?
4. When malware infection is discovered, are response procedures such as minimizing malware spread and damage established and implemented?

## Detailed explanation

> ※ This item is a **relaxed certification criterion (Annex 7-2)** under the special provisions for information security management system certification. The certification criterion/key checkpoints above are the relaxed/adjusted official text, and the detailed explanation/related laws/evidence/nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.10.9 Malware Control], which is the same control domain (under the relaxed criterion, they apply within the scope of the certification criterion/checkpoints above).

To protect information systems and business-use terminals, etc. from malware such as viruses, worms, Trojan horses, and ransomware, protective measures must be established and implemented, including the following.

- User PC usage guidelines (prohibition on opening unclear emails and files, prohibition on downloading and installing unauthorized programs, etc.)
- Malware response guidelines for information systems and personal information processing systems
- Scope of antivirus program installation (information assets subject to possible malware infection)
- Antivirus program installation procedures
- Latest malware prevention and detection activities through antivirus programs, etc.
- Policy for periodic monitoring of malware infection through antivirus programs, etc.
- Setting the automatic update function of security programs such as antivirus software, or a method of updating at least once per day
- Prohibition of installing unauthorized programs such as P2P and web hard drives on information systems and business-use computers
- User training and provision of information, etc.

The latest malware prevention/detection activities must be continuously performed through security programs such as antivirus software.

- Inspection of attachments such as emails for malware infection
- Real-time malware monitoring and remediation
- Periodic malware inspection : setting an automatic virus inspection schedule
- Maintaining the latest version of the antivirus engine : periodic updates, etc.

Security programs such as antivirus software must be kept up to date, and emergency security updates must be performed when necessary.

- Compliance with the antivirus update cycle : automatic update or update at least once per day
- When a malware-related alert is issued or an emergency update notice is given, performing updates accordingly
- When managing antivirus programs using a centralized antivirus management system, establishing protective measures such as access control for the management server and integrity verification for distributed files

When malware infection is discovered, response procedures such as minimizing malware spread and damage must be established and implemented.

- Response procedures when malware infection is discovered (e.g. : disconnecting the network cable, etc.)
- Emergency contact list (e.g.: antivirus vendor contact, related agency contacts, etc.)
- Response report form (including date/time of discovery, response procedures and methods, responder, prevention measures), etc.

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Ensure the Safety of Personal Information Article 9 (Prevention of Malicious Programs, etc.)

## Evidence (examples)

- Malicious program response guidelines/procedures/manuals
- Antivirus program installation status
- Antivirus program configuration screen
- Malicious program response history (response reports, etc.)

## Nonconformity examples

- Cases where antivirus is not installed on some PCs and servers, or the antivirus engine has not been updated to the latest version for a long time
- Cases where users can arbitrarily change the antivirus program configuration (real-time scan, scheduled scan, update settings, etc.) but no additional protective measures have been established accordingly
- Cases where protective measures such as access control for the centralized antivirus management system are inadequate, creating the possibility of a security breach through the centralized management system, or where integrity verification of antivirus patterns is not performed, creating the possibility of malware propagation by malicious users
- Cases where multiple malware infection histories were confirmed on some internal-network PCs and servers, but the infection status, infection route and cause analysis, and corresponding remediation details, etc. could not be confirmed
