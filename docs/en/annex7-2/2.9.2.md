## Certification criterion

When using cloud services, protection measures for administrator access and security settings, among others, shall be established and implemented so that important information and personal information are not leaked or exposed due to unauthorized access, misconfiguration, and similar issues arising from the service type (SaaS, PaaS, IaaS, etc.).

## Key checkpoints

1. Are the responsibilities and roles for information security and personal information protection clearly defined with the cloud service provider and reflected in the contract (SLA, etc.)?
2. When using cloud services, are security control policies such as security configuration and setting standards, security setting change and approval procedures, secure access methods, and the permission scheme established and implemented by assessing the security risks according to the service type so as to prevent unauthorized access, misconfiguration, and similar issues?
3. Are cloud service administrator permissions granted minimally according to role, and are protection measures such as strengthened authentication, encryption, access control, and audit logging applied to prevent unauthorized access to administrator permissions and misuse or abuse of permissions?
4. Are changes to the security settings and the operational status of the cloud service monitored, and is their adequacy reviewed on a regular basis?

## Detailed explanation

> Note: This item is a **relaxed certification criterion (Annex 7-2)** under the special case of the information security management system certification. The certification criterion and key checkpoints above are the official text as relaxed/adjusted, while the detailed explanation, related laws, evidence, and nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for the same control area, Annex 7 [2.10.2 Cloud Security] (under the relaxed criteria, they apply within the scope of the certification criterion and checkpoints above).

The responsibilities and roles for information security and personal information protection shall be clearly defined with the cloud service provider and reflected in the contract (SLA, etc.).

- Roles and responsibilities by cloud service type (examples)

| Cloud service type | Cloud service provider | Cloud service user |
| --- | --- | --- |
| IaaS | - Facility security and access control for the physical area<br>- Security patching of the host OS<br>- Security management of virtual machines such as the hypervisor, etc. | - Security patching of the guest OS, middleware, and applications<br>- Security configuration and settings for the guest OS, middleware, applications, and private network area<br>- Data security<br>- Administrator and user permission management, etc. |
| PaaS | - Roles and responsibilities of the cloud service provider in the IaaS area<br>- Security settings of the network area<br>- Security patching, security configuration, and settings for the guest OS and middleware area | - Application security patching and security settings<br>- Data security<br>- Administrator and user permission management, etc. |
| SaaS | - Roles and responsibilities of the cloud service provider in the IaaS and PaaS areas<br>- Application security patching and security settings<br>- Data security (data-level access control, encryption, etc.), etc. | - Application administrator and user permission management, etc. |

  Note: This may vary depending on the cloud service operator, service configuration, and characteristics, among others.

When using cloud services, security control policies such as security configuration and setting standards, security setting change and approval procedures, secure access methods, and the permission scheme shall be established and implemented by assessing the security risks according to the service type so as to prevent unauthorized access, misconfiguration, and similar issues.

- Risk assessment for the use of external cloud services: consider aspects such as service quality and continuity, legal compliance, and security
- Establishment/implementation of security control policies reflecting the results of the risk assessment of cloud services

  Note: Cloud service security control policy (example) (needs to reflect the characteristics according to the cloud service type)
  - Roles and responsibilities related to security management
  - Virtual network security configuration and access control
  - Cloud service administrator account and permission management (top administrator, administrators by area, etc.)
  - Strengthened authentication for cloud service administrators (OTP, etc.)
  - Security setting standards (authentication, encryption, session management, access control, public settings, lockout for long-term non-use, log recording, backup, etc.)
  - Security setting registration/change/deletion procedures (application, approval, etc.)
  - Adequacy review of security configuration and settings
  - Access control and permission management procedures for the cloud management console
  - Management procedures for issuance, use, and revocation of Access Keys
  - Cloud service remote access paths and methods (VPN, IP address restriction, 2-Factor authentication, etc.)
  - Cloud service security monitoring and alarm/monitoring measures
  - Security audit procedures, etc.

Cloud service administrator permissions shall be granted minimally according to role, and protection measures such as strengthened authentication, encryption, access control, and audit logging shall be applied to prevent unauthorized access to administrator permissions and misuse or abuse of permissions.

- Segmentation of cloud service administrator permissions: top administrator, virtual network administrator, security administrator, DevOps administrator, etc.
- Minimal granting of administrator permissions according to duties and roles
- Application of strengthened authentication for cloud administrator permission access: OTP, security key, etc.
- Application of communication encryption or VPN for the remote access segment
- Detailed log recording and monitoring of cloud administrator access and permission settings, etc.

Changes to the security settings and the operational status of the cloud service shall be monitored, and their adequacy shall be reviewed on a regular basis.

- Alarm setup and monitoring to detect unapproved environment settings and security setting changes to the cloud service
- Regular review and action on whether the security settings of the cloud service are adequate

  Note: Precautions
  - All other necessary protection measures must be applied, including the adequacy of access control such as network access, information system access, database access, and application access in the cloud environment, as well as authentication and permission management, encryption, and system and service security management.

<Source> Cloud Information Security Guide (KISA)

## Related laws

_No individual legal provision directly corresponding to this item is specified._

## Evidence (examples)

- Cloud service contract and SLA
- Cloud service risk analysis results
- Cloud service security control policy
- Status of cloud service administrator permission grants
- Cloud service configuration diagram
- Cloud service security setting status
- History of adequacy reviews of cloud service security settings

## Nonconformity examples

- Where the cloud service contract does not include matters concerning security responsibilities and roles
- Where the permission to change the security settings of the cloud service is excessively granted to employees who do not necessarily need it for their work
- Where internal guidelines require approval from the security officer when changing the access control rules of the private network within the cloud, but numerous access control rules were found to have been registered/changed without going through the approval procedure
- Where internal log files are exposed over the Internet due to a misconfiguration of the cloud service security settings
