# 2.8.3 Log and Access Record Management  _( Annex 7-2 )_

| Field | Value |

## Certification criterion

For information systems such as servers, applications, security systems, and network systems, the organization shall define the log types (user access records, system logs, privilege grant histories, etc.), retention periods, and retention methods, safely retain and manage them so that they are not forged/altered, stolen, or lost, and periodically inspect them in accordance with the log review criteria for access and use.

## Key checkpoints

1. Is a log management procedure established for information systems such as servers, applications, security systems, and network systems, and are the necessary logs generated and retained accordingly?
2. Are the log records of information systems safely retained so that they are not forged/altered, stolen, or lost, and are access privileges to the log records granted on a minimized basis?
3. Are the access records of the personal information processing system retained safely for a certain period, including all necessary items so as to comply with legal requirements?
4. Is a log review and monitoring procedure, including the log review cycle, targets, and methods, established/implemented so that anomalies such as information system errors, misuse/abuse (unauthorized access, excessive inquiry, etc.), and fraudulent acts can be recognized?
5. Are the log review and monitoring results reported to the responsible officer, and are anomalies responded to in accordance with the procedure when detected?
6. Are the access records of the personal information processing system regularly inspected in accordance with the cycle prescribed by the relevant laws?

## Detailed explanation

> ※ This item is a **relaxed certification criterion (Annex 7-2)** under the special exception for information security management system certification. The certification criterion/key checkpoints above are the relaxed/adjusted official original text, while the detailed explanation/related laws/evidence/nonconformity examples below are from the content of the "ISMS-P Certification Criteria Guide" for the same control area, Annex 7 [2.9.4 Log and Access Record Management] (under the relaxed criterion, they apply within the scope of the certification criterion/checkpoints above).

For information systems such as servers, applications, security systems, and network systems, a log management procedure shall be established, and the necessary logs shall be generated and retained accordingly.

- Identify the log types that need to be retained and the target systems

  ※ Major log types (examples)
  - System event logs : logs generated by operating system components (system startup, shutdown, status, error codes, etc.)
  - Network event logs : IP address allocation, traffic logs of major segments
  - Security system logs : administrator access, security policy (rule set) registration/change/deletion, etc.
  - Security-related audit logs : user access records, authentication success/failure logs, file access, account and privilege registration/change/deletion, etc. (servers, applications, security systems, network systems, databases, etc.)
  - Personal information processing system access records : the accessor account, access date and time, access location information, information subject data processed, tasks performed, etc. by which the fact that a personal information handler accessed the personal information processing system can be identified
  - Other information protection-related logs

- Define the log format, retention period, and log retention (backup) method for each system and device

- Establish a log management procedure and generate/retain logs accordingly

The log records of information systems shall be safely retained so that they are not forged/altered, stolen, or lost, and access privileges to the log records shall be granted on a minimized basis.

- Log records shall be backed up using a separate storage device such as storage, and the grant of access privileges to log records shall be minimized so that forgery/alteration and deletion of log records by unauthorized persons do not occur

The access records of the personal information processing system shall be recorded electronically, including all necessary items so as to comply with legal requirements, and safely retained for a certain period.

- Items that must be included in the access records of the personal information processing system

  | Item | Description |
  | --- | --- |
  | Identifier | Identification information of the accessor, such as the personal information handler ID |
  | Access date and time | The time of access or the time the task was performed (year/month/day and hour/minute/second) |
  | Access location information | The accessor IP address, etc. |
  | Information subject data processed | The information subject's ID, customer number, student number, employee number, etc. |
  | Task performed | Inquiry, change, entry, deletion, output, download, etc. of personal information |

- Retention period of the personal information processing system access records

  | Field | Retention period |
  | --- | --- |
  | Access records of personal information handlers - in the case of a personal information processing system that processes personal information on 50,000 or more information subjects | At least 2 years |
  | Access records of personal information handlers - in the case of a personal information processing system that processes unique identifying information or sensitive information | At least 2 years |
  | Access records of personal information handlers - in the case of a key telecommunications business operator that, as a personal information controller, is registered under Article 6(1) of the "Telecommunications Business Act" or has reported under the proviso of the same paragraph | At least 2 years |
  | When none of the above three conditions applies | At least 1 year |

- The personal information access records need to be safely retained so that they are not forged/altered, stolen, or lost

  ※ Safe retention methods for access records (examples)
  - Perform access record backups on a constant basis and retain them on a separate auxiliary storage medium, a separate storage device, object storage, etc. other than the personal information processing system
  - To prevent forgery/alteration of access records, use overwrite-prevention media such as CD-ROM, DVD-R, and WORM (Write Once Read Many)
  - When backing up access records on modifiable media (hard disks, magnetic tapes, etc.), retain/manage information that can verify whether forgery/alteration has occurred (MAC value, digital signature value, etc.) on a separate device to ensure integrity

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Ensure the Safety of Personal Information Article 8 (Retention and Inspection of Access Records)

## Evidence (examples)

- Log management procedure
- Log record details
- Access control details for log storage devices
- Personal information access record details

## Nonconformity examples

- Where detailed criteria and procedures for the log recording targets, methods, retention periods, review cycle, personnel in charge, etc. are not established
- Where the maximum size of important logs, such as security event logs and application and service logs (Windows Server 2008 or higher), is not set sufficiently, so they are not recorded/retained for the period specified in the internal criteria
- Where log records for important Linux/UNIX-family servers are not separately backed up or appropriately protected, so users' command execution records and access histories, etc. can be deleted at will
- Where, upon checking the records of access to the personal information processing system, the accessor's account, access date and time, and accessor IP address information are retained, but information related to the information subject data processed and the task performed (inquiry, change, deletion, download, etc.) is not retained
- Where, due to insufficient capacity of the log server, the access records of the personal information processing system remain for only 2 months
- Where a personal information controller retains the personal information handler access records of a personal information processing system that processes the personal information of 100,000 information subjects for only 1 year
