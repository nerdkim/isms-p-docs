# 2.9.3 Public Server Security  _( Annex 7-2 )_

| Field | Value |

## Certification criterion

For servers exposed to external networks, the organization shall separate them from the internal network and establish/implement reinforced protection measures such as vulnerability assessment, access control, authentication, and procedures for collecting/storing/disclosing information.

## Key checkpoints

1. When operating a public server, are protection measures for it established/implemented?
2. Is the public server installed in a DMZ (Demilitarized Zone) area separated from the internal network and protected through security systems such as an intrusion prevention system?
3. When personal information and important information must be posted or stored on a public server, are authorization and posting procedures such as approval by the responsible person established/implemented?
4. Is it periodically checked whether the organization's important information is being exposed through websites and web servers, and when exposure of important information is recognized, are measures such as immediately blocking it taken?

## Detailed explanation

> Note: This item is a **relaxed certification criterion (Annex 7-2)** under the special provisions for Information Security Management System certification. The certification criterion/key checkpoints above are the relaxed/adjusted official original text, while the detailed explanation/related laws/evidence/nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for the same control area, Annex 7 [2.10.3 Public Server Security] (under the relaxed criteria, they apply within the scope of the certification criterion/checkpoints above).

- When operating a public server such as a web server, protection measures for it shall be established/implemented.
  - Building a secure server by installing an SSL (Secure Socket Layer)/TLS (Transport Layer Security) certificate, etc., when personal information is transmitted/received through the web server
  - Installing antivirus software and configuring updates
  - Installing the latest security patches for applications (web server, openssl, etc.), operating systems, etc.
  - Removing unnecessary services and blocking ports
  - Prohibiting installation of unnecessary software, scripts, executable files, etc.
  - Prohibiting exposure of unnecessary pages such as error handling pages and test pages
  - Performing periodic vulnerability assessment, etc.

- The public server shall be installed in a DMZ area separated from the internal network and protected through security systems such as an intrusion prevention system.
  - Applying access control policies through an intrusion prevention system, etc., so that intrusion into the internal network through the public server is impossible even if the public server is compromised
  - Applying strict access control policies when the public server in the DMZ needs to connect to information systems such as databases and WAS (Web Application Server) located in the internal network

- When personal information and important information must be posted or stored on a public server, authorization and posting procedures such as approval by the responsible person shall be established/implemented.
  - In principle, prohibiting the storage of personal information and important information within web servers in the DMZ segment, and applying authorization procedures and protection measures when unavoidably necessary for business
  - Performing prior review and approval procedures when posting personal information and important information on a website
  - Taking measures to prevent personal information and important information from being exposed to those without access rights through external search engines, etc.

- It shall be periodically checked whether the organization's important information is being exposed through websites and web servers, and when exposure of important information is recognized, measures such as immediately blocking it shall be taken.
  - Periodically checking through search engines, etc., and applying necessary measures
  - When exposure of important information is recognized, taking blocking measures on the website and requesting the relevant search engine operator to ensure that it is not continuously exposed through caches, etc.

## Related laws

_No individual legal provision directly corresponding to this item is specified._

## Evidence (examples)

- Network configuration diagram
- Website information disclosure procedures and records (application/approval/posting history, etc.)
- Records of checks on whether personal information and important information are exposed

## Nonconformity examples

- A case where, due to a vulnerability in a website open to the internet, someone else's personal information can be accessed without viewing rights through a Google search
- A case where internal rules require an approval procedure when posting personal information on a website, but many instances exist where personal information was posted without complying with this
- A case where, in a web application such as a bulletin board, posts written by others can be arbitrarily modified/deleted, or password-protected posts can be viewed
