# 2.9.6 Patch Management  _( Annex 7-2 )_

| Field | Value |
|---|---|
| Domain | 2. Protective Measure Requirements |

| Item | 2.9.6 Patch Management |
| Criteria type | Annex 7-2 (special exceptions for certification, relaxed certification criteria) |

## Certification criterion

The latest patches must be applied to prevent security incidents caused by vulnerabilities in software, operating systems, security systems, and the like. However, if applying the latest patches is difficult after reviewing the impact on services, separate supplementary measures must be established and implemented.

## Key checkpoints

1. Are patch management policies and procedures for operating systems (OS) and software established and implemented according to the characteristics and importance of each asset, such as servers, network systems, security systems, and PCs?
2. For key servers, network systems, security systems, and the like, is the patch application status of the installed OS and software managed periodically?
3. Where applying the latest patches to remediate vulnerabilities is difficult due to service impact and similar factors, are supplementary measures established?
4. For key servers, network systems, security systems, and the like, is patching via public internet access restricted?
5. Where a patch management system is used, are sufficient protective measures such as access control established?

## Detailed explanation

> * This item is a **relaxed certification criterion (Annex 7-2)** under the special exceptions of the Information Security Management System certification. The certification criterion and key checkpoints above are the officially relaxed/adjusted text, while the detailed explanation, related laws, evidence, and nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.10.8 Patch Management], which is the same control area (under the relaxed criteria, they apply within the scope of the certification criterion/checkpoints above).

Patch management policies and procedures for the OS and software must be established and implemented according to the characteristics and importance of each asset, such as servers, network systems, security systems, and PCs.

- Targets for patch application: servers, network systems, DBMS, applications, commercial software, open source, security systems, PCs, and the like
- Patch cycle: reflecting asset importance and characteristics
- Method for checking patch information
- Pre-review procedure before patch deployment
- Emergency patch application procedure
- Security review when patches are not applied
- Patch personnel and responsible persons
- Contact information for patch-related vendors (manufacturers) and the like

For key servers, network systems, security systems, and the like, the patch application status of the installed OS and software must be managed periodically.

- Manage as a list so that the version information of the operating system and software installed on key servers, network systems, security systems, and the like, the patch application status, and the application date of each patch can be verified
- Periodically check whether the latest security patches need to be applied

* Sites for checking the end of service support (EOS or EOL) for major OSes (examples)
- MS Windows: https://support.microsoft.com/ko-kr/lifecycle/search
- Red Hat Linux: https://access.redhat.com/support/policy/updates/errata
- CentOS: https://wiki.centos.org/About/Product
- AIX: https://www-01.ibm.com/support/docview.wss?uid=isg3T1012517
- HP-UX: https://hpe.com/info/hpuxservermatrix
- Solaris: https://www.oracle.com/technetwork/server-storage/solaris/overview/releases-jsp-140987.html

Where applying the latest patches to remediate vulnerabilities is difficult due to service impact and similar factors, supplementary measures must be established.

- Since applying patches to operational systems may affect system availability, apply them after sufficiently analyzing the impact through impact analysis and similar means according to the defined procedures, taking into account the importance and characteristics of the operational system
- Where immediate patch application is difficult depending on the operating environment, establish the reasons and additional supplementary measures, report them to the responsible person, and manage the status

For key servers, network systems, security systems, and the like, patching via public internet access must be restricted.

- However, where unavoidable, apply after establishing protective measures through prior risk analysis and obtaining approval from the responsible person

Where a patch management system (PMS) is used, since it may be exploited as a distribution point for malicious code to internal network servers or PCs, sufficient protective measures such as access control must be established for the patch management system server, management console, and the like.

- Access control measures for the patch management system itself: block access by anyone other than authorized administrators, change default passwords, remove security vulnerabilities, and the like
- File integrity checks when distributing update files, and the like

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Ensure the Safety of Personal Information Article 9 (Prevention of Malicious Programs, etc.)

## Evidence (examples)

- Patch application management policies/procedures
- Patch application status by system
- Results of impact analysis related to patch application

## Nonconformity examples

- Where, on some systems, OS patches have not been applied for a long period without valid reason or approval from the responsible person
- Where some systems are using an OS version whose service support has ended (EOS), but no corresponding response plan or supplementary measures have been established
- Where the latest patches are applied to commercial software and the OS, but for open source programs (openssl, openssh, Apache, etc.) no procedure or responsible person is designated to check and apply the latest patches, so the latest security patches are not being applied
