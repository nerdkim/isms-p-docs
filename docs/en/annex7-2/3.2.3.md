## Certification criterion

When access is required to information stored within the mobile communications terminal device of the data subject (user) or to functions installed on the mobile communications terminal device, this must be notified so that the data subject (user) can clearly recognize it, and the consent of the data subject (user) must be obtained.

## Key checkpoints

1. When access permission is required for information stored within the data subject's (user's) mobile communications terminal device or for functions installed on the mobile communications terminal device, is this notified so that the user can clearly recognize it, and is the consent of the data subject (user) being obtained?
2. In cases where the access permission is not one that is strictly necessary to provide the relevant service within the mobile communications terminal device, is service provision not being refused even if the data subject (user) does not consent?
3. Are methods provided for the data subject (user) to consent to and withdraw consent for the relevant access permission within the mobile communications terminal device?

## Detailed explanation

> * This item is a **relaxed certification criterion (Annex 7-2)** under the special provisions for information security management system certification. The certification criterion / key checkpoints above are the officially relaxed/adjusted original text, while the detailed explanation / related laws / evidence / nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [3.2.3 Protection of User Device Access], which is the same control area (under the relaxed criterion, these apply within the scope of the certification criterion / checkpoints above).

When access permission is required for information stored within the data subject's (user's) mobile communications terminal device or for functions installed on the mobile communications terminal device, the relevant matters must be notified so that the data subject (user) can clearly recognize them, and the consent of the data subject (user) must be obtained.

* Scope of mobile communications terminal devices
- Applies to smartphones and tablet PCs capable of mobile communications
- 2G mobile communications terminal devices are excluded from the scope, as they are effectively not an environment in which apps can operate
- Devices that do not use a mobile communications network and merely perform functions such as Bluetooth, Wi-Fi, or tethering are excluded from the scope of application
- For smartwatches, considering that it is currently difficult to implement notification/consent functions for access permissions due to constraints such as screen size, it is recommended that only essential access permissions be set for now (however, from the point at which devices with notification/consent functions implemented are manufactured, the same rules apply as for smartphones and tablet PCs)

- The permissions by which an app can access information stored within the smartphone and installed functions must be minimized to the scope necessary for the service
- Before obtaining consent for access permissions, access permissions that are strictly necessary to provide the relevant service (hereinafter "essential access permissions") and access permissions that are not strictly necessary (hereinafter "optional access permissions") must be distinguished, and after clearly notifying the data subject (user) of the items requiring access permission and the reasons therefor in an easy-to-understand manner, consent to essential/optional access permissions must be obtained separately from the data subject (user)
  - (For essential access permissions) The following must be notified: (1) the items of information and functions requiring access permission, and (2) the reason access to the relevant information and functions is required
  - (For optional access permissions) In addition to (1) and (2) above, (3) the fact that the user may decline to consent to granting the access permission must be notified

In cases where the access permission is not one that is strictly necessary to provide the relevant service within the mobile communications terminal device, service provision must not be refused even if the data subject (user) does not consent.

Methods for the data subject (user) to consent to and withdraw consent for the relevant access permission within the mobile communications terminal device must be provided.

- (Operating systems that allow individual consent selection, Android 6.0 or higher and iPhone) Even if the data subject (user) has already consented to access permissions, they can reset the access permissions for each app by using the per-app/per-access-permission consent withdrawal function provided by the relevant operating system
- (Operating systems that do not allow individual consent selection) Because a per-access-permission denial function is not implemented, in principle only essential access permissions are set, so if the data subject (user) wishes to withdraw consent to such essential access permissions, they can simply delete the already installed app. However, even with such an operating system, if the app itself has implemented optional access permissions and a function allowing the user to choose whether to consent to them, the user can reset the access permissions by using the consent withdrawal function provided by the relevant app

* For details, refer to the "Guide on Personal Information Protection for Smartphone App Access Permissions"

## Related laws

- Network Act Article 22-2 (Consent to Access Permissions)

## Evidence (examples)

- App access permission consent screen
- App access permission configuration status

## Nonconformity examples

- Cases where a smartphone app has excessively set permissions to access personal information areas within the smartphone, such as the address book, photos, and text messages, even though they are unnecessary for the service
- Cases where an information and communications service provider's smartphone app accesses information stored within the smartphone and installed functions without providing notification of and obtaining consent for access permissions
- Cases where, when obtaining consent for a smartphone app's access permissions, a permission that corresponds to an optional item is notified as an essential permission when obtaining consent
- Cases where a smartphone app supporting a version below Android 6.0, for which individual consent for access permissions is not possible, is distributed with optional access permissions also set, making it impossible to decline the optional access permissions
