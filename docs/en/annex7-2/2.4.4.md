## Certification criterion

Taking into account legal requirements, external threat factors, and the like, procedures for managing the passwords used by information system users as well as by customers, members, and other data subjects (users) shall be established and implemented.

## Key checkpoints

1. Are secure user password management procedures and composition rules for information systems established and implemented?
2. Are password composition rules established and implemented so that data subjects (users) can use secure passwords?
3. Are the authentication means of personal information handlers or data subjects applied and managed securely?

## Detailed explanation

> Note: This item is a **relaxed certification criterion (Annex 7-2)** under the special provisions of information security management system certification. The certification criterion and key checkpoints above are the relaxed/adjusted official text, while the detailed explanation, related laws, evidence, and nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.5.4 Password management], which belongs to the same control area (under the relaxed criterion, they apply within the scope of the certification criterion and checkpoints above).

Password management procedures and composition rules shall be established and implemented so that users and administrators can set and use secure passwords.

- Examples of password composition rules (enforced systematically except where unavoidable)

| Field | Value |
| --- | --- |
| Applying combination rules | At least 8 characters combining two or more of the following types: letters, numbers, special characters<br>At least 10 characters if composed of letters only (however, a password composed of numbers only may be vulnerable) |
| Setting a change cycle | Set a password validity period and change it periodically (however, whether to change periodically and the change cycle are decided internally taking into account risk assessment results and the like) |
| Restricting easy-to-guess passwords | Restrict the use of passwords that are easy to guess, such as repeated identical characters, character strings adjacent on the keyboard, serial numbers, consecutive numbers, birthdays, phone numbers, and other easily guessed personal information, as well as passwords similar to the ID |
| Restricting reuse of the same password | Restrict the reuse of previously used passwords when changing a password |

- Examples of password management procedures
  - Use passwords only after changing the initial or temporary password set at system introduction
  - Apply masking when handling passwords (input, change)
  - Restrict recording/storing passwords on paper, files, mobile devices, and the like, and apply protection measures such as encryption when recording/storing is unavoidable
  - Change the password without delay if an intrusion incident occurs or password exposure is suspected
  - Perform identity verification procedures when resetting a password due to loss and the like
  - Manage administrator passwords in accordance with confidentiality grades, and the like

Password composition rules shall be established and implemented so that data subjects (users) can set and use secure passwords.

- Refer to the password composition rules for users and personal information handlers, and apply password composition rules at an appropriate level taking into account the characteristics and risk level of the service, and the like
- Establish a secure reissuance procedure through identity verification and the like in case of password loss or theft, and the like

The authentication means of personal information handlers or data subjects shall be applied and managed securely.

- When a password is used as the authentication means of a personal information handler or data subject, establish and apply secure password composition rules
- When authentication means other than passwords (certificates, PINs, biometrics, security tokens, and the like) are used, apply protection measures so that the authentication means is not stolen or misused by unauthorized persons

[Reference] Application/management of the authentication means of personal information handlers or data subjects (Standards for Measures to Secure the Safety of Personal Information, Article 5, Paragraph 5)

(5) The personal information controller shall apply and manage the authentication means of personal information handlers or data subjects securely.

## Related laws

- Personal Information Protection Act, Article 29 (Duty of safety measures)
- Standards for Measures to Secure the Safety of Personal Information, Article 5 (Management of access rights)

## Evidence (examples)

- Password setting screens of web pages, information systems, and personal information processing systems
- Password management policies and procedures

## Nonconformity examples

- A case where information security and personal information protection policies, guidelines, and the like set standards for password creation rules, but some information systems and personal information processing systems use passwords that differ from the internal guidelines
- A case where internal password regulations require that a temporary password be issued upon reset and be mandatorily changed, but in practice the temporary password continues to be used as is
- A case where internal password regulations set a password change cycle for users and personal information handlers and require its implementation, yet passwords are used as is without being changed
