# 2.8.1 Change Management  _( Annex 7-2 )_

| Field | Value |

## Certification criterion

Procedures shall be established and implemented so that all changes to information system related assets can be managed, and the impact on the system's performance and security shall be analyzed prior to a change.

## Key checkpoints

1. Are procedures for changes to information system related assets (hardware, operating systems, commercial software packages, etc.) established and implemented?
2. Is the impact on performance and security analyzed before carrying out changes to information system related assets?

## Detailed explanation

> ※ This item is a **relaxed certification criterion (Annex 7-2)** under the special provisions for information security management system certification. The above certification criterion / key checkpoints are the officially relaxed/adjusted original text, while the detailed explanation / related laws / evidence / nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.9.1 Change Management], which is the same control domain (under the relaxed criteria, they apply within the scope of the above certification criterion / checkpoints).

Procedures for changes to information system related assets (hardware, operating systems, commercial software packages, etc.) shall be established and implemented.

- When changes to information system related assets are required, such as operating system upgrades, installation of commercial software, functional improvements to applications in operation, network configuration changes, and expansion of CPU/memory/storage, establish and implement a formal procedure for the change

  ※ Matters to be included in the change procedure (examples)
  - Change request
  - Review and approval by the responsible person
  - Change verification and validation
  - Identification and change of related documents (asset inventory, operation manuals, configuration diagrams, etc.)
  - Change history management, etc.

The impact on performance and security shall be analyzed before carrying out changes to information system related assets.

- When changes to information system related information assets are required, analyze the impact of the change on security, performance, business, etc. (the need to change policies of security systems such as firewalls, problems and impact levels when changing policies, etc.)
- Implement the change so as to minimize the impact caused by the change
- Consider recovery measures for change failure in advance

## Related laws

_No individual legal provision directly corresponding to this item is specified._

## Evidence (examples)

- Change management procedures
- Records of change management execution (application/approval, change details, etc.)
- Results of impact analysis for changes

## Nonconformity examples

- A case where change work was recently carried out for DMZ segment redundancy, but no evidence of performing/approving an assessment of the security risks and performance that could arise after the change was confirmed
- A case where network change work was recently carried out, but related review and notification were not sufficiently conducted, so it was not properly reflected in the network configuration diagram and in the access control lists (ACLs) of some access control systems (intrusion prevention systems, database access control systems, etc.)
- A case where a change management system was built to analyze/consult on the impact on performance and security when information systems are brought in or changed and to manage the related history, but system changes are possible without going through that system, and the related changes are not properly reviewed
