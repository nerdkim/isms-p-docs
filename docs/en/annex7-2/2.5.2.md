# 2.5.2 Information System Access  _( Annex 7-2 )_

| Field | Value |

| Criterion type | Annex 7-2 (Certification special case, relaxed certification criteria) |

## Certification criterion

For information systems such as servers and network systems, the users allowed access, the access restriction method, and safe access means shall be defined and controlled.

## Key checkpoints

1. For each information system such as servers, network systems, and security systems, are the users allowed access to the operating system (OS), the locations from which access is permitted, and the access means defined and controlled?
2. When no work is processed for a certain period of time after connecting to an information system, is the system connection automatically blocked?
3. Are services unrelated to the purpose of use of the information system removed?
4. Are information systems that provide key services operated as independent servers?

## Detailed explanation

> Note: This item is a relaxed certification criterion (Annex 7-2) under the special case of Information Security Management System certification. The certification criterion / key checkpoints above are the relaxed/adjusted official original text, while the detailed explanation / related laws / evidence / nonconformity examples below are the content of the "ISMS-P Certification Criteria Guide" for Annex 7 [2.6.2 Information System Access], the same control area (under the relaxed criterion, they are applied within the scope of the certification criterion / checkpoints above).

For each information system such as servers, network systems, and security systems, the users allowed access to the operating system (OS), the locations from which access is permitted, and the access means shall be defined and controlled.

- Account and privilege application/approval procedures
- Granting an individual account to each user and restricting the use of shared accounts
- Periodic review and up-to-date management of account usage status: whether long-unused accounts or unnecessary accounts exist, etc.
- Access location restriction: restricting the accessing party's IP address, etc.
- Consideration of strengthened authentication means for special privileges such as administrators: certificates, OTP, etc.
- Application of safe access means: SSH, SFTP
- Access control measures for connections between servers within the same network area, etc.

When no work is processed for a certain period of time after connecting to an information system, measures shall be taken so that the system connection is automatically blocked.

- Setting the session duration considering the characteristics of each server, the work environment, the magnitude of risk, legal requirements, etc.

Services or ports that are unrelated to the purpose of use of the information system or that may cause security incidents shall be identified and removed or blocked.

- Implementing additional security functions for unsafe services, protocols, and daemons
- Unless unavoidable, restricting the use of unsafe services/protocols such as Netbios, File-Sharing, Telnet, and FTP, and using safe technologies such as SSH, SFTP, and IPSec VPN

Servers that provide key services shall be operated as independent servers.

- Web servers, database servers, applications, etc. that directly provide services to the outside or that store/process sensitive information shall use independent servers rather than being used as shared equipment

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Secure the Safety of Personal Information Article 6 (Access Control)

## Evidence (examples)

- Information system operating system account list
- Server security settings
- Server access control policy (SecureOS management screen, etc.)
- Server and network configuration diagram
- Information asset list

## Nonconformity examples

- When a server administrator, accessing a Windows server located in the IDC from the office, uses the terminal service for access, but no session timeout is set for the terminal service, so the session is not blocked even after a long period of inactivity
- When connections between servers are not properly restricted, so that a specific user, after connecting to a server authorized to them, can pass through that server to also connect to other unauthorized servers
- When access is made using unsafe connection protocols (telnet, ftp, etc.) without a valid reason or supplementary measures, and unnecessary services and ports are open
- When the access control policy requires all access to servers to go through the server access control system, but a bypass path exists that allows access to servers without going through the server access control system
