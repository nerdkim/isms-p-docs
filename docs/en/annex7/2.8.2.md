# 2.8.2 Review and Testing of Security Requirements

## Certification criterion

To review whether an information system has been introduced or implemented in accordance with predefined security requirements, review criteria and procedures such as compliance with legal requirements, inspection of the latest security vulnerabilities, secure coding implementation, and privacy impact assessment shall be established and carried out, and improvement measures shall be performed for the problems found.

## Key checkpoints

1. When introducing, developing, or changing an information system, is testing performed to verify whether the security requirements defined in the analysis and design phases have been effectively applied?
2. Is vulnerability inspection performed to verify whether the information system has been developed safely in accordance with secure coding standards and the like?
3. Are procedures such as establishing improvement plans and checking their implementation carried out so that problems found during testing and vulnerability inspection can be improved promptly?
4. Do public institutions, in accordance with the relevant laws, perform an impact assessment through an impact assessment agency in the analysis/design phase when newly developing or changing a personal information processing system, and reflect the results in the development and change?

## Detailed explanation

When introducing, developing, or changing an information system, review criteria and procedures shall be established to verify whether the security requirements defined in the analysis and design phases have been effectively applied, and testing shall be performed accordingly.

- Perform testing before acceptance of an information system to verify conformity with acceptance criteria
  - Establish acceptance criteria and procedures to verify whether the information system has been developed/changed and introduced in a way that satisfies the predefined security requirements
  - Before accepting the information system, verify conformity with the predefined acceptance criteria through testing and the like, then decide whether to accept it
  - It is necessary to verify system security settings, whether unnecessary default accounts have been removed, whether the latest security vulnerability patches have been applied, and so on
- Perform testing on whether the developed/changed and implemented functions satisfy the predefined security requirements
  - Reflect this in the test plan, checklists, test result reports, and the like

Vulnerability inspection shall be performed to verify whether the information system has been developed safely in accordance with secure coding standards and the like.

- After coding is completed, inspect compliance with secure coding standards and conventions, and inspect whether technical security vulnerabilities exist
  - Verify the source code to check whether the system is implemented in accordance with secure coding standards (e.g., using source code verification tools)
  - For programs whose coding is completed, inspect whether vulnerabilities are exposed through vulnerability inspection tools or simulated diagnosis in an environment identical to the operating environment

Procedures such as establishing improvement plans and checking their implementation shall be carried out so that problems found during testing and vulnerability inspection can be improved promptly.

- Establish and carry out procedures such as improvement planning, internal reporting, and implementation checking so that the problems found can be improved before the system goes live
- When improvement before the system goes live is difficult for unavoidable reasons, prepare measures to reduce the risk, such as impact assessment, supplementary measures, and internal reporting

Public institutions shall, in accordance with the relevant laws, perform a privacy impact assessment through an impact assessment agency in the analysis/design phase when newly developing or changing a personal information processing system, and reflect the results in the development and change.

- When public institutions establish a plan for the new development or change of a personal information processing system, they shall review whether it is subject to the mandatory privacy impact assessment, and if it is a mandatory target, establish an impact assessment plan and secure the related budget

  ★ Targets subject to mandatory privacy impact assessment (Article 35 of the Enforcement Decree of the Personal Information Protection Act)
  1. (Condition of 50,000 persons) A personal information file involving the processing of sensitive information or unique identifying information: where the personal information file to be built/operated or changed contains the personal information of 50,000 or more data subjects
  2. (Condition of 500,000 persons) Where linkage with another personal information file is intended: where, as a result of linkage with another personal information file built/operated inside or outside the relevant public institution, the personal information of 500,000 or more data subjects is included
  3. (Condition of 1,000,000 persons) A general personal information file: where the personal information file to be built/operated or changed contains the personal information of 1,000,000 or more data subjects
  4. (In case of change) Where the operating system of a personal information file, such as the personal information search system, is to be changed after receiving an impact assessment: the changed part of the relevant personal information file
  ※ Target personal information files: personal information files that can process personal information electronically

- Public institutions shall, in the analysis/design phase when newly developing or changing a personal information processing system, perform an impact assessment through an impact assessment agency designated by the Personal Information Protection Commission, and reflect the results in the development and change
  - The status of designated impact assessment agencies can be verified on the "Privacy Portal (www.privacy.go.kr)"
  - For the impact assessment performance procedures, assessment criteria, and the like, refer to the "Privacy Impact Assessment Performance Guide"
- Public institutions shall submit the privacy impact assessment report to the Personal Information Protection Commission before the personal information processing system goes live and within 2 months after the completion of the impact assessment
  - Register the impact assessment report in the Integrated Privacy Support System (intra.privacy.go.kr)
  - The Personal Information Protection Commission or the head of the public institution may disclose a summary of the impact assessment report
- Manage whether the improvement requirements resulting from the privacy impact assessment are implemented
  - Establish a detailed implementation plan for the improvement requirements
  - Regularly check the implementation status
  - Where measures within the period are unavoidably difficult, record/report the valid reasons and establish an implementation plan for future measures
  - The head of a public institution that has received an impact assessment report shall submit to the Personal Information Protection Commission, within 1 year, the implementation status of the parts identified as items for improvement (implementation check confirmation of the improvement plan)

※ Privacy impact assessment procedure

## Related laws

- Personal Information Protection Act Article 33 (Privacy Impact Assessment)
- Notice on Privacy Impact Assessment

## Evidence (examples)

- Information system acceptance test results
- Requirements traceability matrix
- Test plan, test result report
- Vulnerability inspection result report
- Privacy impact assessment report
- Implementation check confirmation of the privacy impact assessment improvement plan

## Nonconformity examples

- The case where, after the information system is implemented, the security requirements defined in the internal development-related guidelines and documents are not tested
- The case where some important inspection items, such as input value validity checks, are omitted from the application test scenarios and technical vulnerability inspection items
- The case where, during implementation or testing, whether known technical vulnerabilities exist is not inspected, or improvement measures for confirmed vulnerabilities are not carried out without valid reasons or approval
- The case where a public institution newly builds a personal information file and a personal information processing system subject to the mandatory impact assessment, such as processing the unique identifying information of 50,000 or more data subjects, but does not conduct the impact assessment
- The case where a public institution performs an impact assessment but does not submit the impact assessment report to the Personal Information Protection Commission even though 2 months have passed since it received the impact assessment report from the impact assessment agency
- The case where internal guidelines are prepared to review the impact on the existing operating environment and its security (such as vulnerability inspection) when introducing a new system, but for some recently introduced information systems, security reviews such as vulnerability inspection were not performed at the time of acceptance
