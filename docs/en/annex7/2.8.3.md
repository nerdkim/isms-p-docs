# 2.8.3 Separation of Test and Production Environments

| Field | Value |
|---|---|
| Domain | 2. Protective Measure Requirements |
| Section | 2.8 Security in Information System Introduction and Development |
| Item | 2.8.3 Separation of Test and Production Environments |
| Applicable certification | ISMS `●` / ISMS-P `●` |
| Korean source | 2.8.3 시험과 운영 환경 분리 |

## Certification criterion

Development and test systems shall, in principle, be separated from production systems in order to reduce the risk of unauthorized access to and modification of production systems.

## Key checkpoints

1. Are the development and test systems of the information system separated from the production system?
2. Where separation of the development and production environments is difficult for unavoidable reasons, are security measures such as mutual review, supervisory monitoring, change approval, and ensuring accountability in place?

## Detailed explanation

The development and test systems of the information system shall be separated from the production system.

- In principle, development and test systems and the production system are configured separately.
- Access control measures between the development and test systems and the production system are established and implemented so that developers cannot access the production system unnecessarily.

Where separation of the development and production environments is difficult for unavoidable reasons, security measures such as mutual review, supervisory monitoring, change approval, and ensuring accountability shall be provided.

- Where separation of the development and production environments is unavoidably difficult due to reasons such as a very small organizational scale, a shortage of human resources, or system characteristics, appropriate compensating controls are applied to reduce the resulting security risks.
  - Mutual review among personnel
  - Change approval
  - Monitoring and auditing by supervisors
  - Backup and recovery measures, ensuring accountability, etc.

## Related laws

_No individual legal provision directly corresponding to this item is specified._

## Evidence (examples)

- Network configuration diagram (including test environment configuration)
- Status of access control applied between the production environment and the development/test environment

## Nonconformity examples

- Where source code changes are performed directly in the production environment without configuring a separate development environment and without valid justification or approval.
- Where the development system and the production system are unavoidably operated without separation, but records of mutual review, monitoring, etc. for this are missing.
- Where a development system is configured separately, but access from the development environment to the production environment is not controlled, so that developers can access the production system unnecessarily by way of the development system.
