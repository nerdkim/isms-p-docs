# 2.6.4 Database Access

| Field | Value |
|---|---|
| Domain | 2. Protective Measure Requirements |

## Certification criterion

The organization shall identify the information stored/managed within the database, such as the list of tables, and shall establish/implement an access control policy based on the importance of the information and the types of applications and users.

## Key checkpoints

1. Is the information stored/managed in the database, such as the list of database tables, being identified?
2. Are the applications, information systems (servers), and users that need access to information within the database clearly identified and controlled in accordance with the access control policy?

## Detailed explanation

The information stored/managed in the database, such as the list of tables, shall be identified and continuously kept up to date and managed.

- Identify the list of tables used in the database, the information stored, correlations, etc.
- Identify the storage location of important information and personal information (database and table name/column name) and the current status (number of records, whether encrypted, etc.)
- Regularly survey the database status and keep it up to date

The applications, information systems (servers), and users that need access to information within the database shall be clearly identified and controlled in accordance with the access control policy.

- Divide database access privileges into administrator (DBA) and user, and establish/implement an access control policy by duty (access control at the table, view, column, and query level based on the principle of least privilege, etc.)
- Restrict access to tables and columns containing important information so that only those with business authority to process them can access them
- Distinguish accounts granted DBA privileges from accounts granted other privileges such as inquiry
- Restrict shared use of accounts used by applications and user accounts
- Restrict the commands usable per account
- Delete unused accounts, test accounts, default accounts, etc.
- Automatically block connection when no task is performed for a certain period of time
- Restrict database access by unauthorized persons
- Restrict databases storing personal information from being located in publicly exposed networks such as the DMZ
- Block unauthorized access from other network zones and other servers
- Restrict the IP addresses, ports, and applications permitted to access the database
- As a rule, take measures so that general users can access the database only through applications, etc.

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Ensure the Safety of Personal Information Article 5 (Management of Access Privileges), Article 6 (Access Control)

## Evidence (examples)

- Database status (tables, columns, etc.)
- List of database connection accounts/privileges
- Database access control policy (database access control system management screen, etc.)
- Network configuration diagram (database zone, etc.)
- Information asset inventory

## Nonconformity examples

- A case where a database storing/processing large volumes of personal information is operated on physically the same server without being separated from a web application accessible via the internet
- A case where developers and operators access the operational database by sharing the account used in the application
- A case where internal regulations require database access privileges to be restricted by object, but database access privileges are granted to operators in bulk, so that excessive access privileges are granted even to operators who do not need to access the personal information tables
- A case where a database access control solution has been introduced and operated, but the IP addresses, etc., of database connectors are not appropriately restricted, so that connections are being made to the database by bypassing the database access control solution
- A case where the status of tables in the database storing personal information is not identified, so that large volumes of unnecessary personal information are stored without being destroyed in a temporarily created table
