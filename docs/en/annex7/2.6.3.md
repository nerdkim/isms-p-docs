# 2.6.3 Application Access

| Field | Value |
|---|---|
| Domain | 2. Protective Measure Requirements |
| Section | 2.6 Access Control |
| Item | 2.6.3 Application Access |
| Applicable certification | ISMS `●` / ISMS-P `●` |
| Korean source | 2.6.3 응용프로그램 접근 |

## Certification criterion

Application access rights shall be restricted according to each user's duties and the sensitivity of the information they access, and criteria shall be established and applied so that exposure of unnecessary information or sensitive information can be minimized.

## Key checkpoints

1. To control access to sensitive information, are application access rights granted differentially according to the user's duties?
2. Are sessions with no input for a certain period automatically blocked, and is the number of concurrent sessions for the same user limited?
3. Are administrator-only applications (administrator web pages, management consoles, etc.) access-controlled so that unauthorized persons cannot access them?
4. Are relevant criteria established and applied so that consistency of display-restriction protective measures for personal information and sensitive information can be secured?
5. Are applications implemented and operated so that unnecessary exposure (viewing, screen display, printing, downloading, etc.) of personal information and sensitive information can be minimized?

## Detailed explanation

To control access to sensitive information, application access rights shall be granted differentially according to the user's duties.

- Clearly identify applications used internally (back-office systems, membership management systems, etc.)
- Identify personal information processing systems that handle personal information among the applications
- Establish a classification scheme for user and personal information handler access rights (an access rights classification table, etc.) based on the principle of least privilege
- Implement application functions so that rights to process sensitive information and personal information (input, view, change, delete, download, output, etc.) can be set in a granular manner
- Establish and implement procedures for granting accounts and rights to the identified applications and personal information processing systems
- Retain records related to granting/changing/deleting rights to review the appropriateness of access rights

Sessions with no input for a certain period shall be automatically blocked, and the number of concurrent sessions for the same user shall be limited.

- Determine and apply the session-retention time by considering the characteristics of each application and duty, the magnitude of risk, etc.
- For personal information processing systems, take measures so that system access is automatically blocked when no work is processed for a certain period or longer, in accordance with legal requirements
- Display a warning message and restrict access upon concurrent connection with the same account

Administrator-only applications (administrator web pages, management consoles, etc.) shall be access-controlled so that unauthorized persons cannot access them.

- Block external disclosure of administrator-only applications and take access-restriction measures such as via IP address
- Where external disclosure is unavoidably necessary, apply secure authentication means (OTP, etc.) or secure connection means (VPN, etc.)
- Regularly monitor the access logs and event logs of administrators (users) and personal information handlers
- Upon discovering anomalous signs, carry out detailed investigation, internal reporting, etc. in accordance with predefined procedures

To secure consistency of display-restriction measures for personal information and sensitive information, relevant criteria shall be established/applied.

- Examples of criteria for display-restriction measures of personal information and sensitive information
  1. Name : the middle character of the name (however, for a 2-character name, the last character; for a name of 4 characters or more, the characters excluding the first and last characters)
  2. Resident registration number : the last 7 of the 13 digits
  3. Telephone number, mobile phone : the exchange number
  4. Address : the building number below the road name and the digits of the detailed address
  5. Email address : the remainder of the ID excluding the first 2 characters
  6. Card number : 6 digits from the 7th digit
  7. IP address : bits 17-24 (Ver. 4), bits 113-128 (Ver. 6), etc.

Applications shall be implemented and operated so that unnecessary exposure (viewing, screen display, printing, downloading, etc.) of personal information and sensitive information can be minimized.

- When outputting personal information and sensitive information from applications (personal information processing systems, etc.) (printing, screen display, downloading, etc.), specify the purpose and minimize the output items according to the purpose
- Output the minimum personal information within the scope of access rights to the personal information processing system, according to the form and purpose of the work, its type, location, and other conditions and environments
- Unless absolutely necessary for work, take measures so that "like" searches are not possible when searching for personal information
- When searching for personal information, use exact-match search (equal search) or search conditions of two or more items so that unnecessary or excessive information is not retrieved
- Take measures so that personal information is not saved in the form of hidden fields in office files (Excel, etc.)
- Take measures so that unnecessary personal information is not output through viewing the web page source, etc.

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Ensure the Safety of Personal Information Article 5 (Management of Access Rights), Article 6 (Access Control), Article 12 (Safety Measures upon Output/Copying)

## Evidence (examples)

- Application access rights classification scheme
- Application account/rights management screen
- Application user/administrator screens (personal information viewing, etc.)
- Records of application session time and whether concurrent connection is permitted
- Records of application administrator access log monitoring
- Information asset inventory
- Personal information viewing and search screens of the personal information processing system
- Personal information masking standard
- Personal information masking application screen

## Nonconformity examples

- A case where an error exists in the access-control function of some screens among the personal information processing screens of an application, so that personal information is exposed even to users without the right to view personal information
- A case where the administrator page of an application is open to the external internet while secure authentication means are not applied
- A case where, without a valid reason, session timeout or concurrent connection of the same user account is not restricted for an application
- A case where, when personal information is downloaded through an application, the file excessively contains information unnecessary for work such as resident registration numbers
- A case where the personal information search screen of an application excessively permits "like" searches, so that all users can query all customer information even by surname alone, exceeding their scope of work
- A case where different masking criteria are applied to the same personal information item across the screens of the personal information processing system, due to reasons such as no display-restriction measure criteria being established or such criteria not being complied with
- A case where personal information is displayed masked on the screen of the personal information processing system, but the full, unmasked personal information is exposed through viewing the web browser source
