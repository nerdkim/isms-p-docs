# 2.6.1 Network Access

| Field | Value |
|---|---|
| Domain | 2. Protection Measure Requirements |
| Section | 2.6 Access Control |
| Item | 2.6.1 Network Access |
| Applicable certification | ISMS `●` / ISMS-P `●` |
| Korean source | 2.6.1 네트워크 접근 |

## Certification criterion

To control unauthorized access to the network, management procedures such as IP management and terminal authentication shall be established and implemented, and network separation (DMZ, server farm, DB zone, development zone, etc.) and access control shall be applied according to business purpose and importance.

## Key checkpoints

1. Are all paths that can access the organization's network identified, and is the internal network controlled so that only authorized users can access it in accordance with the access control policy?
2. Are network areas physically or logically separated according to services, user groups, the importance of information assets, and legal requirements, and is access control applied between each area?
3. Are criteria for assigning IP addresses by network band established, and are measures such as assigning private IPs applied when external connection is not required for DB servers, etc.?
4. Are transmission section protection measures in place when connecting to physically remote IDCs, branches, agencies, etc.?

## Detailed explanation

All paths that can access the organization's network shall be identified, and network access control management procedures shall be established and implemented so that related risks, such as unauthorized access to the network, can be effectively prevented and responded to.

- Control of unauthorized IP use, such as assigning IP addresses to information systems, personal information processing systems, PCs, etc. in accordance with an approval procedure
- Control of internal network access by unauthorized persons and terminals
- Blocking of unnecessary services and ports installed on network devices, etc.

Network areas shall be physically or logically separated according to services, user groups, the importance of information assets, and legal requirements, and access control shall be applied between each area.

- Determine the level of network separation and inter-area access control for core business areas through risk assessment

| Access control area | Access control application example |
| --- | --- |
| DMZ | Public servers such as web servers and mail servers for external services are located in the DMZ. Direct connections from the internet to internal systems not passing through the DMZ are blocked |
| Server farm | Configured separately from other network areas. Access control policy applied to allow only access by authorized internal users |
| DB zone | The network area where databases storing important information such as personal information are located is separated from other network areas |
| Operator environment | The operator network area operating servers, security devices, network devices, etc. is separated from the general user network area |
| Development environment | The network used for development work (development servers, test servers, etc.) is separated from the operational network |
| External party area | The network area used by external personnel (outsourced services, civil affairs offices, training rooms, etc.) is separated from the internal business network |
| Other | For the business network, network band separation criteria are established and operated according to the characteristics and importance of the work. When using cloud services, access control criteria reflecting the characteristics of the cloud environment are established and implemented. However, if it is difficult to distinguish server farms and database farms considering the size of the enterprise, etc., it is necessary to apply supplementary measures based on risk assessment results, etc. (host-based access control, etc.) |

- Between network areas separated according to the access control policy, control is applied using intrusion prevention systems, network device ACLs, etc., to allow only access to the services necessary for performing work between network areas

Criteria for assigning IP addresses by network band shall be established, and when important systems such as database servers do not require connection to the outside, they shall be assigned private IPs so that direct access from the outside is impossible.

- Keep the IP address assignment status up to date, and manage it securely at a confidential or higher level so that it is not leaked externally
- Use a private IP address scheme for the addressing scheme in the internal network, and apply the NAT (Network Address Translation) function so that the internal addressing scheme is not exposed externally
- When assigning private IP addresses, use private IP address bands in accordance with international standards

* Private IP address bands
  / A Class : 10.0.0.1 ~ 10.255.255.255
  / B Class : 172.16.0.1 ~ 172.31.255.255
  / C Class : 192.168.0.1 ~ 192.168.255.255

When connecting to physically remote IDCs, branches, agencies, partner companies, customer centers, etc., a secure connection environment shall be configured using dedicated lines or VPN (Virtual Private Network), etc.

## Related laws

- Personal Information Protection Act Article 29 (Duty of Safety Measures)
- Standards for Measures to Secure the Safety of Personal Information Article 6 (Access Control)

## Evidence (examples)

- Network configuration diagram
- IP management ledger
- Information asset inventory
- Firewall rules

## Nonconformity examples

- A case where, as confirmed through the network configuration diagram and interviews, when connecting between information systems and personal information processing systems used at external sites and servers located in the IDC, data is transmitted and received via a general internet line, so communication using VPN or a dedicated network as specified in internal regulations is not being carried out
- A case where the IP addresses of some important servers such as database servers located in the internal network are set to public IPs contrary to internal regulations, and network access blocking is not applied
- A case where a server farm is configured, but due to inadequate network access control settings, access from the internal network to the server farm is excessively allowed
- A case where the network provided to external parties (external developers, visitors, etc.) is not separated from the internal business network without separate controls
- A case where, contrary to internal regulations, the internal network can be accessed and used simply by connecting a network cable without applying protection measures such as MAC address authentication and installation of mandatory security software
